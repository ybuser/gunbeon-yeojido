# 군번여지도 강원 디자인 기획 v2

작성일: 2026-09-07 · 대상: ① 웹·앱 개발 부문 1차 심사용 모바일 웹

**상태:** 벤치마크에서 도출한 디자인 계획을 화면 구조와 코드로 구현한 상태다. 이 문서는 현재 구현을 읽어 정리한 디자인 명세이며, 브라우저 UX 검증 완료나 실제 사용자 사용성 입증을 뜻하지 않는다.

## 1. 디자인의 목적

**“오늘 함께 다녀올 곳을 고르고, 돌아갈 여유를 확인하고, 가족과 기록한다.”** 이 순서가 화면의 중심이다. 강원 접경 5군의 장소와 장병·가족의 제한된 시간을 먼저 보여준다. 고유 기능명과 데이터 설명은 사용자가 그 정보가 필요한 단계에서 만난다.

핵심 경험은 **둘러보기 → 지도·미션 → 내 여행에 담기 → 가족 제안·여행 기록**으로 연결된다. 부모는 가족 탭에서 별도로 여행안을 만들 수 있다. 초대코드는 여행을 시작하기 위한 필수 조건이 아니라 허용된 정보를 함께 보고 제안하는 협업 수단이다.

기존 서비스의 지역특화·복귀 안전마진·부모 공동 사용자·비무장 패스포트·휴가회수 레이더·민감정보 미수집 원칙은 유지한다. 군사 장식 대신 실제 강원 풍경과 관광 정보가 정체성을 만든다.

## 2. 벤치마크를 반영한 선택

| 공식 자료에서 확인한 구조 | 군번여지도에 적용한 선택 |
|---|---|
| Wanderlog의 지도와 일정 연결, 번호 핀·장소 목록 대응 | 지도와 번호 목록을 같은 미션 화면에 배치하고 양쪽에서 같은 장소 상세를 연다. |
| AllTrails의 사진 탐색 카드와 상세 핵심 수치 | 홈은 장소 사진·미션 제목·총 소요시간·도보 추정·복귀 여유를 중심으로 비교한다. |
| Polarsteps의 계획 단계와 기록 단계 구분 | 내 여행에서 계획한 미션과 여행 기록을 나누고, 기록 이후에 스탬프·공유를 연결한다. |
| 국내 조사에서 확인한 지역·장소 탐색과 내 여행·동행 계획 | 지역 선택을 홈으로 당기고 가족을 주요 탭으로 유지한다. 기능명을 사용자의 행동 중심 내비게이션으로 재배치한다. |

글로벌 근거는 직접 확인한 [Wanderlog 공식 스크린샷·기능 설명](https://play.google.com/store/apps/details?hl=en-US&id=com.wanderlog.android), [AllTrails 공식 스크린샷](https://play.google.com/store/apps/details?hl=en-US&id=com.alltrails.alltrails), [Polarsteps 공식 계획 도움말](https://support.polarsteps.com/hc/en-us/articles/24265886208914-How-do-I-plan-my-trip)이다. 국내 근거와 관찰 한계는 [국내 벤치마크 보고서](design_benchmark_korea.md), 원본 화면 관찰은 [글로벌 벤치마크 보고서](design_benchmark_global.md)에 정리했다. 위 적용안은 자체 설계 판단이며 경쟁사의 성과나 사용자 성공률을 증명하는 주장이 아니다.

## 3. 시각 체계

| 요소 | 현재 구현과 목적 |
|---|---|
| 바탕·본문 | 흰색 `#FFFFFF`, 차콜 `#22272E`. 넓은 베이지 면적과 표지형 장식을 줄이고 장소 정보의 대비를 확보한다. |
| 행동색 | 파랑 `#246FE5`. 주요 CTA와 선택 상태에 사용해 다음 행동을 찾게 한다. |
| 보조면·경계 | 옅은 회색 `#F5F6F8`, 경계 `#E7EAF0`. 정보 묶음을 가볍게 구분한다. |
| 상태색 | 초록·주황·빨강은 시간 판정에 한정하고 수치·상태 문구를 함께 표시한다. |
| 사진 | 제공된 해당 장소 사진을 우선 사용한다. 고석정은 확인된 공개 사진을 사용하고, 사진이 없으면 중립적인 빈 상태를 보여준다. |
| 구성 단위 | 탐색은 사진 카드, 일정은 번호 목록, 판단은 수치 요약, 편집·상세는 Sheet, 근거는 펼침 영역으로 구분한다. |
| 브랜드 표현 | 한글 서비스명과 짧은 여행 문장. 여권·스탬프는 내 여행 기록에 배치한다. 영어 kicker·가짜 좌표·장식 도장을 기본 화면의 중심에 두지 않는다. |

브랜드를 설명하는 큰 문단보다 여행 대상과 판단값이 먼저 보이도록 구현했다. 색상·간격·글자 크기가 실제 기기에서 충분한지는 별도 시각·접근성 검증 대상이다.

## 4. 주요 화면과 행동

### 둘러보기

`오늘, 강원 어디 갈까요?` 아래에 철원·화천·양구·인제·고성·춘천·속초 지역 선택을 둔다. 남은 시간과 동행·이동수단은 짧은 조건 요약으로 보여주고 `내 조건으로 미션 찾기`에서 편집을 연다.

미션은 실제 장소 사진, 여행 성격, 장소 이름, 총 소요시간·도보 추정·복귀 여유를 같은 위치에 배치한다. 사진 또는 제목을 누르면 선택한 미션의 지도 화면으로 이동한다. 하단에는 가족 여행 준비 진입을 둔다. 사진 출처와 추정 안내를 유지하며 후보 로딩·없음·재조회 상태를 구분한다.

### 조건 편집: 3단계 Sheet

| 단계 | 질문 | 입력 |
|---|---|---|
| 1 | 누구와 어디에서 만날까요? | 역할·지역·상황·동행·이동수단 |
| 2 | 언제까지 돌아오면 되나요? | 가용시간·공개 거점 도착 목표·만남/복귀 공개 거점 |
| 3 | 어떤 하루가 편할까요? | 경험·전체 도보 상한·추가 여유·날씨 보정 |

편집 중에는 임시값을 사용하고 마지막 버튼에서 적용한다. 단계 수, 이전·다음 행동과 최종 `이 조건으로 미션 보기`를 명시한다. 부모 역할로 적용하면 선택한 지역·이동수단·도보 조건을 가족 화면으로 넘긴다. 거점 이후 부대까지의 이동·수속 시간을 별도로 남겨야 한다는 안내와 민감정보 미입력 안내는 관련 단계에 둔다.

### 지도·미션

조건 요약 → 지도와 복귀 여유 → 미션 종류 → 제목·소요시간·도보 → 공개 거점·번호 장소 목록 → 근거 순서로 구성한다. 지도 핀과 장소 행은 동일한 장소 상세로 이어진다. 카카오맵 길찾기는 장소별 외부 행동으로 분리한다.

`공개 거점까지 복귀 여유`와 시간상 안전권·주의권·비추천 상태를 함께 표시한다. 추정 안내는 수치 가까이에 유지하고, 산식과 장소별 출발 전 조건은 펼쳐 읽게 한다. 하단의 대표 행동은 `이 미션 내 여행에 담기`다. 저장과 방문 기록은 별개 동작이다.

장소 상세 Sheet에는 제공된 방문·편의 정보, 관광공사 상세 응답, 출처, 외부 길찾기를 모은다. 실제 운영 정보가 없을 때는 미제공 상태를 알린다. 현재 장소 상세는 정보 확인 중심이며 장소 제거·대체 편집까지 구현된 것으로 설명하지 않는다.

### 가족

지역·방문 날짜·이동수단·도보·식사 선호로 **초대 없이** 독립 여행안을 만든다. 결과는 장소 순서, 걷기 추정, 주차 정보 확인, 실내 후보, 식사 후보, 무장애 정보로 나뉜다. 도보 상한 초과와 정보 미확인 상태도 함께 보여준다.

초대 연결은 별도 영역이다. 연결 후 허용된 미션·선호·기록 범위가 보이며 제안 권한이 있을 때 `이 미션을 가족에게 제안`을 사용할 수 있다. 제안은 내 여행에서 `살펴보기`로 연결된다. 현재는 같은 브라우저에서 역할을 바꾸는 체험이며 다른 기기와 동기화하지 않는다. 제안의 검토와 원본 일정 확정·저장을 동일한 동작으로 표현하지 않는다.

### 내 여행

`계획한 미션 / 여행 기록`을 구분한다. 스탬프가 없는 항목은 계획, 스탬프가 있는 항목은 기록으로 분류한다. 자동 완료 판정이 아니라 사용자가 직접 남긴 기록이라는 뜻이다.

각 항목에 기록 단계, 현재 조건으로 다시 보기, 공유 카드를 둔다. 비무장 패스포트는 강원 5군별 기록 수로 요약한다. 초대코드 생성·공유 범위·해제는 패스포트의 펼침 영역, 휴가회수 레이더는 방문 준비 진입으로 배치한다. 공유 Sheet는 정확한 시간·좌표·부대 정보가 없는 문구와 SVG 카드 저장을 제공한다.

현재 저장 항목은 미션 식별자·제목·지역·스탬프다. `현재 조건으로 다시 보기`는 현재 데이터와 조건으로 재구성하므로 저장 당시의 장소·시간 전체를 보존한 확정 일정으로 설명하지 않는다.

### 방문 준비와 이용 안내

휴가회수 레이더는 현충시설 후보, 공식 확인·부대 확인·방문 준비 체크리스트, 휴가 씨앗 기록을 유지한다. 보상 자격·휴가 지급을 보장하지 않는다. 이용 안내에는 출처·데이터 수신 상태·계산 가정·정보 부족·개인정보 원칙을 모아 심사위원이 활용 근거를 찾을 수 있게 한다.

## 5. 기존 6개 기능의 유지·재배치

| 기존 기능 화면 | v2 진입 | 유지 내용 |
|---|---|---|
| 홈·온보딩 | 둘러보기 + 조건 편집 | 지역 탐색·역할·상황·시간·동행·이동·복귀 목표 |
| 복귀 미션·지도 | 지도·미션 | 미션 조합·복귀 여유·번호 장소·상세·외부 길찾기 |
| 부모 브리핑룸 | 가족 | 독립 조건·여행안·식사·편의 정보·허용 범위·제안 |
| 비무장 패스포트 | 내 여행 | 계획 저장·개인 기록·5군 챕터·초대·안전 공유 |
| 휴가회수 레이더 | 내 여행의 방문 준비 진입 | 후보·공식 확인·체크리스트·휴가 씨앗 |
| 데이터·출처 | 상단 이용 안내·하단 출처·미션 출처 | API 활용·갱신/실패 상태·가정·미수집 원칙 |

주요 탭은 **둘러보기 / 지도·미션 / 가족 / 내 여행** 네 개다. 기능 범위를 네 개로 축소한 것이 아니라, 여섯 기능의 진입 우선순위를 여행 과정에 맞게 정했다.

## 6. 반응형 구성

| 화면 폭 | 코드에 반영된 동작 |
|---|---|
| 760px 초과 | 상단 탭. 미션은 왼쪽 일정·오른쪽 고정 지도, 가족 입력·연결 영역과 내 여행·패스포트 요약은 병렬 배치. Sheet 폭은 최대 580px. |
| 760px 이하 | 하단 고정 4탭, 세로 문서 흐름. 지도 높이 300px, 그 아래 복귀 여유와 일정. 저장 CTA는 하단 탭 위. 가족·내 여행은 단일 열. Sheet는 화면 폭 전체와 최대 91dvh. |
| 370px 이하 | 탐색 미션 카드를 한 열로 전환하고 폼도 한 열로 정리한다. |

모바일 탐색 카드는 현재 371~760px에서 두 열이다. 제목은 16px, 주요 입력은 16px이며 보조 정보 일부는 12~14px다. 따라서 ‘모든 문구가 부모 세대에 충분히 크다’는 판단은 아직 하지 않는다. 안전영역 여백과 동작 감소 설정 대응은 코드에 반영했으며, 실제 키보드·주소창·하단 바 간섭은 미검증이다.

## 7. 문구와 정보 공개 원칙

- **사용자 행동을 먼저 말한다.** `미션 보기`, `조건 변경`, `가족에게 제안`, `현재 조건으로 다시 보기`처럼 결과를 예상할 수 있게 쓴다.
- **값의 성격을 수치와 함께 말한다.** `도보 추정`, `공개 거점까지 복귀 여유`, `시간상 안전권`을 쓰고 실제 교통·부대 복귀를 보장하는 말은 쓰지 않는다.
- **미확인과 불가를 구분한다.** 빈 값을 예약 불필요·주차 가능·부모 동행 적합으로 바꾸지 않는다. 여행 결정을 바꾸는 제한은 요약 단계에서도 알아볼 수 있어야 한다.
- **협업의 현재 범위를 명시한다.** 같은 브라우저 체험·공유 권한·직접 기록·공적 인증 아님을 해당 행동 근처에서 알린다.
- **정보 출처를 유지한다.** 관광공사 정보는 `출처: ⓒ한국관광공사`로 표시하며 이미지 출처와 데이터 상태를 구분한다. 서비스 내부 용어·API 상세는 이용 안내와 정보 상세에서 설명한다.

## 8. 검증 상태와 다음 확인

**이번에 확인한 것:** 화면 컴포넌트·상태 전이·저장 구조·스타일의 정적 검토. 4탭, 3단계 편집, 장소 상세, 가족 독립 입력과 제안 진입, 계획/기록 구분, 문맥별 보조 기능이 코드에 반영되어 있다.

**아직 입증하지 않은 것:** 모바일/데스크톱 브라우저의 렌더 완성도, 모든 클릭 흐름의 성공, 실제 지도 타일·조작, 사용자 이해도, 접근성 적합성, 디자인 변경의 정량 효과. 현재 API HTTP 연결 결과는 [런타임 검증](app_runtime_verification.json)과 [배포 검증](deployed_runtime_verification.json)을 참고한다. HTTP 응답 성공을 브라우저 사용성 검증으로 취급하지 않는다.

다음 UX 검증은 다음 여섯 행동을 기준으로 한다.

1. 첫 방문자가 지역·시간·동행을 이해하고 첫 미션을 찾는가. 초기 기본값과 공개 거점 가정을 확인할 수 있는가.
2. 좁은 두 열 카드에서도 장소·추정값·중요 방문 조건을 읽는가. 접힌 상세나 모바일 숨김 때문에 결정적인 제한이 사라지지 않는가.
3. 지도 핀과 번호 목록이 같은 장소 상세를 열며, 닫기·뒤로가기·탭 변경 후 상태를 이해할 수 있는가. 핀 강조·스크롤 복원까지 완료된 것으로 미리 판단하지 않는다.
4. Sheet의 키보드·포커스·닫기·이전·적용 동작이 안정적이며 하단 저장 버튼이 콘텐츠를 가리지 않는가.
5. 부모가 초대 없이 여행안을 만들고, 초대 후 허용 범위 안에서 제안을 남기며, 제안 검토와 일정 저장을 구분하는가.
6. 저장과 방문 기록·공적 인증을 구분하고, 재구성되는 계획·같은 브라우저 초대·API 실패·사진 없음 상태를 오해하지 않는가.

가족 방문 날짜는 실제 예보·시설 운영 확정값이 아니며 식사 선호는 메뉴·알레르기 적합성 검증을 뜻하지 않는다. 이러한 현재 기능 범위를 시각적 완성도와 별개로 유지·검증한다.
