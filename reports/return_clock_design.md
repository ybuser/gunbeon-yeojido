# 복귀시계·미션 엔진 상세 설계

- 작성일: 2026-09-07
- 문서 성격: 구현 전 연구·설계. 이 문서의 수치와 알고리즘은 제안한 제품 기본값이며 실제 도로·교통·기상 모델의 검증 결과가 아니다.
- 범위: 공개 민간 거점 출발 → 2~4개 장소 → 같은 공개 거점 복귀를 계산한다. 공개 거점 이후 부대까지의 이동이나 소속 부대의 복귀 인정 여부는 계산하지 않는다.
- 사용자에게 보일 기본 문구: **“안전마진은 공개 거점 도착까지의 참고값입니다. 실제 교통과 소속 부대 복귀 규정은 직접 확인해 주세요.”**

## 1. 제품이 답할 질문과 답하지 못하는 질문

핵심 질문은 “설정한 공개 거점 도착 시각 안에 이 관광 미션을 마칠 여유가 얼마나 남는가?”다. 사용자가 입력하는 복귀 기준시각은 앱 내부에서 `public_hub_deadline`으로 취급하고 UI 입력에는 **“공개 거점 도착 목표”**를 병기한다. 군 복귀 마감과 공개 거점 도착 목표를 같은 값으로 오해하게 만들지 않는다.

입력 단계에 “부대 이동·수속에 필요한 시간을 스스로 남긴 뒤 공개 거점 도착 목표를 정해 주세요”를 한 번 설명한다. 실제 부대명, 군번, 부대 위치, 근무표, 휴가증 원문, 부대 이동경로를 요구하지 않는다. 목표시각은 개인 기기에만 저장하며 부모·공유 카드에 포함하지 않는다.

공개 거점에서 시작하는 계획의 계산값이다. 출발 전 사용자가 실제로 다른 곳에 있다면 그 장소에서 공개 거점까지의 이동은 포함되지 않았음을 출발 입력과 산식에서 드러낸다. 자동 위치 추적으로 출발 거점을 추측하지 않는다.

## 2. 입력과 상태

| 입력 | 형식·기본 정책 | 미입력·이상값 처리 |
| --- | --- | --- |
| 공개 거점 | 운영자가 허용한 공개 장소 ID | 알 수 없는 ID·좌표·부대명 자유입력 거절 |
| 강원 권역 | 5군 또는 춘천·속초 관문 | 해당 권역의 장소만 후보로 사용 |
| 상황·역할·동행 | 열거값 | 추정에 영향 없는 항목은 선택 가능 |
| 남은 시간 | 2시간·4시간·8시간·1박2일 | 당일 프리셋은 처음 목표시각을 제안하는 데 사용 |
| 목표일·시각 | Asia/Seoul의 명시적 날짜+시각 | 날짜가 없는 자정 넘김을 자동 추정하지 않음 |
| 이동수단 | car / transit / taxi_bus / unknown | unknown은 교통 확인 전 안전권 불가 |
| 최대 연속 도보 | 10·20·30·60분 등 | 모르면 “도보 조건 미설정”; 접근성 확인으로 대체하지 않음 |
| 전체 도보 상한 | 사용자 선택, 선택적 | 없으면 연속 도보 제한만 평가 |
| 날씨 상태 | live / verified_snapshot / simulated / unknown | unknown을 맑음으로 치환하지 않음 |
| 예약·방문 준비 | 미확인 / 준비 중 / 사용자가 준비 완료 | 사용자 확인이 시설 운영의 실시간 보증은 아님 |
| 진행 상태 | planned / active / completed / abandoned | 완료는 사용자 여행 기록으로만 사용 |

프리셋과 목표시각이 서로 다른 경우 **사용자가 마지막으로 확정한 목표시각을 기준**으로 한다. 프리셋을 바꿀 때 목표시각도 바뀐다는 것을 즉시 보여주고, 목표시각 직접 수정 후에는 프리셋을 “직접 설정”으로 표시한다. 두 값을 독립적인 시간 제약처럼 중복 차감하지 않는다.

## 3. 날짜·현재시각·재계산

### 당일

- 현재 시각과 목표시각은 초 단위의 절대 시점으로 계산하고 표시는 한국 시각으로 한다.
- 23:00에 01:00을 입력하면 다음 날로 자동 변경하지 않는다. “목표일을 내일로 선택해 주세요”를 표시한다.
- 목표시각이 현재보다 같거나 이르면 입력 오류 또는 “목표시각이 지났어요” 상태다. 미션을 안전권으로 분류하지 않는다.
- 2시간 프리셋은 최초 선택 당시의 현재시각+120분으로 목표를 고정한다. 매 재계산마다 다시 2시간을 주면 시간이 무한히 늘어나므로 금지한다.

### 1박2일

- 첫날·다음 날을 명시적으로 나누고 목표 날짜와 휴식 구간을 표시한다. 24시간을 관광 가능 시간으로 취급하지 않는다.
- 초기 설계의 휴식 기본값은 8시간이며 사용자가 수정할 수 있다. 이는 권장 수면량에 관한 건강 지침이 아니라 일정상 확보한 휴식 구간이다.
- 숙소 예약·운영이 미확인인 경우 “숙박 확인 필요”를 표시한다. 숙박 미확인 상태에서 완결된 1박 미션이 확보됐다고 표현하지 않는다.
- 숙소는 별도 공개 장소 노드로 표현하고 2~4개 방문 장소 수에 포함한다. 실제 운영조건이 확보되지 않았다면 완성된 추천 대신 “1박 일정 초안”으로 제공한다.
- 관광시설의 날짜별 운영시간·휴무를 알 수 없다면 다음 날도 열려 있다고 가정하지 않는다. 밤중에 관광시설 방문을 배치해 여유시간을 확보하지 않는다.
- 첫날 종료와 둘째 날 출발 사이 휴식은 실제 타임라인의 시간 구간으로 계산한다. 이미 타임라인에 반영한 휴식을 안전마진 식에서 다시 빼지 않는다.

### 시간 경과

- 화면 표시 중 30초마다 재계산하고, 탭이 다시 보이거나 기기가 절전에서 돌아오면 즉시 재계산한다.
- 네트워크 연결과 무관하게 현재 기기 시각을 사용한다. 기기 시각 변경을 감지하면 “기기 시각 기준으로 다시 계산했어요”를 표시한다.
- 목표시각은 저장해도 남은 분·안전권 판정은 저장하지 않는다. 재접속할 때 현재 시각으로 다시 구한다.
- 출발하지 않은 `planned` 미션은 항상 지금 출발하는 전체 일정으로 평가한다.
- `active` 미션은 사용자가 선택한 공개 장소 체크포인트 이후의 남은 일정만 평가한다. 과거 계획대로 이미 이동했다고 자동 가정하지 않는다. 현재 체크포인트를 모르면 “남은 일정 계산을 위해 현재 공개 장소를 선택해 주세요”로 전환한다.
- 체류 중이라는 상태에서는 실제 체류 시작 시점과 남은 체류시간을 사용한다. 단순 방문 스탬프만으로 이동 완료·정시 도착을 추정하지 않는다.
- 심사용 고정 시각은 별도 **“시연 시계”** 모드로 제공할 수 있으나 화면 상단에 고정 표시하고 실제 시각 모드와 분리한다. 시연 모드에서 만든 결과를 실시간 결과라고 표현하지 않는다.

## 4. 거리와 이동 추정

경로 순서는 `공개 거점 → P1 → P2 → … → Pn → 같은 공개 거점`이다. 각 구간에 대해 위경도 기반 Haversine 직선거리(km)를 구한다. 이 직선거리를 실제 도로 길이나 길찾기 결과로 표시하지 않는다.

`추정 도로거리 = 직선거리 × 도로우회계수`

초기 운영계수는 1.6으로 제안한다. 이는 검증 전 보수적인 제품 파라미터다. 강·산·민통선·해안에서 일률 계수가 실제 경로를 대표하지 못하므로 “거리 기반 추정” 출처를 붙인다. 운영자가 공식 길찾기로 확인한 구간은 별도 검증된 경로값을 사용할 수 있고 확인 일시와 출처를 기록한다. 서로 다른 출처의 구간을 합쳤다면 구간별 출처를 보여준다.

| 수단 | 시연용 속도 기본값 | 구간별 추가 시간 | 판정 제한 |
| --- | ---: | --- | --- |
| 자차 car | 35 km/h | 매 방문지 주차·승하차 8분 | 주차 가능 여부가 미확인이면 별도 확인 상태 |
| 대중교통 transit | 25 km/h | 승차 대기 30분 + 공개 구간 접근 10분 | 노선·운행·막차 미검증이면 안전권 불가 |
| 택시+버스 taxi_bus | 25 km/h | 호출/승차 대기 20분 + 접근 10분 | 구간별 수단 미정이면 전체를 이 가정으로 계산하고 교통 확인 필요 |
| 미정 unknown | 25 km/h | 대기 30분 + 접근 10분 | “교통 가정으로 계산 중”; 안전권 불가 |

위 속도·대기·주차 시간은 **실측/예보값이 아닌 초기 시연 기본값**이다. 실제 교통 API가 성공하면 해당 구간의 ETA·대기시간으로 교체하되 같은 항목을 중복으로 더하지 않는다. 버스 노선이 존재하는지는 직선거리로 판단할 수 없다. 운행 불가가 확인된 구간은 이동시간이 길어지는 정도가 아니라 실행 불가 조건으로 취급한다.

구간 이동시간은 분 단위 올림한다. 위치가 다른 두 장소 사이에서 계산값이 1분 미만이면 최소 1분으로 한다. 같은 장소 ID에 대한 중복 노드는 제거하지만, 좌표가 같다는 이유만으로 다른 시설을 자동 병합하지 않는다. 누락·범위 밖 좌표, 0/0, 비유한 수치가 있으면 “이동 추정 불가”로 분류하며 0분으로 통과시키지 않는다.

공개 거점 이후 군 시설로 향하는 경로는 생성·저장·공유하지 않는다. 외부 지도 링크는 개별 관광 장소나 공개 거점의 길찾기만 연결하며 군 복귀 경로라는 제목을 붙이지 않는다.

## 5. 체류·도보·날씨·버퍼

### 체류와 가족 동행

장소별 체류시간은 출처가 있는 정보 또는 편집자가 정한 값이며 “권장 체류 추정”으로 표시한다. 장소 체류시간에 포함된 기본 걷기 시간을 또 그대로 가족 버퍼로 더하지 않는다.

`가족 추가시간 = 동행 설정에 따른 추가 휴식 + 기본 도보 대비 늘어난 도보시간`

- 초기 추가 휴식 예: 방문 장소당 5분. 이 값도 시연 기본값으로 관리한다.
- 연속 도보시간과 전체 도보시간은 별도로 판단한다. 여러 장소 사이 차량 이동이 있다고 해서 한 시설 내 긴 보행 부담이 사라지지 않는다.
- 도보시간을 모르면 “도보 정보 확인 필요”다. 부모 동행 설정만으로 접근성 적합도를 높이지 않는다.
- 연속 도보 제한을 초과한 장소는 가족 조건 부적합으로 표시한다. 가중점수만 낮춘 채 가족 친화 추천에 올리지 않는다.
- 주차·경사로·엘리베이터·휠체어 정보는 각 원본 필드를 별도로 표시한다. 빈 필드는 없음이나 있음으로 치환하지 않는다.

### 날씨

시연의 맑음·비·눈/강풍 조건은 명확한 **“날씨 시뮬레이션”** 칩과 계산 내역으로 드러낸다. 실제 관측이나 예보처럼 날짜별 사실로 말하지 않는다. live일 때도 예보의 발행 시점·유효시각·해당 지역을 검사한다.

초기 시연 보정 예는 비: 전체 추정 이동시간의 15% + 야외 장소당 10분이다. 눈/강풍은 숫자 가산만으로 해결하지 않고 야외 방문을 “오늘 비추천” 처리해 실내 대체지를 제시한다. 이 비율은 기상 교통 연구에서 검증된 값이 아니며 사용자에게 가정임을 밝힌다. 실제 기상 특보나 운영 중단을 확인한 경우에는 시뮬레이션 기본값보다 확인된 제한이 우선한다.

날씨 데이터가 없으면 “날씨 미확인”이고 가상의 맑음 아이콘을 보여주지 않는다. 수치 산식에는 미확인 보정값 0을 넣어 안전을 주장하지 말고, 날씨를 제외한 잠정 여유를 표시하며 최종 상태는 확인 필요로 제한한다.

### 일반 버퍼

기본 혼잡 버퍼는 `max(15분, 전체 추정 이동시간 × 10%)`의 올림값으로 제안한다. 실시간 혼잡을 측정했다는 의미가 아니므로 이름은 “기본 여유시간”으로 표시한다. 실제 혼잡 ETA가 들어온 경우 기본 여유가 다른 위험을 위한 값인지 구분하고 교통 지연을 중복 가산하지 않는다.

## 6. 안전마진 산식과 화면 판정

`안전마진 = 목표시각 − 평가 현재시각 − 남은 체류 − 남은 구간이동 − 남은 거점이동 − 대기/주차 − 기본 여유 − 날씨 추가시간 − 가족 추가시간 − 남은 숙박/휴식`

모든 차감항목은 분으로 정규화한다. 거점 복귀 구간이 전체 구간이동 합계에 이미 들어있으면 별도로 다시 빼지 않는다. 구현에서는 구간의 유형을 나누어 정확히 한 번만 합산한다. 사용자에게는 “머무름 / 장소 이동 / 거점 복귀 / 대기·주차 / 가족 휴식 / 날씨 가정 / 기본 여유 / 숙박·휴식” 내역을 펼쳐볼 수 있게 한다.

| --- | --- | --- |
| 45분 이상 | 안전권 후보 | 가정상 공개 거점 목표까지 여유가 있음 |
| 15분 이상~45분 미만 | 주의권 | 지연에 취약하므로 짧은 대안 우선 |
| 15분 미만 | 오늘 비추천 | 양수라도 여유가 너무 적음 |
| 0분 미만 | 오늘 비추천 | 예상 목표 초과분을 함께 표시 |
| 계산 불가 | 계산 보류 | 원인을 먼저 보여줌 |

위 구간은 제품 초기 정책이며 공식 안전 기준이 아니다. 수치가 양수여도 모든 미션을 안전권으로 표시하지 않는다.

시간 상태와 별도로 실행 조건을 `확인됨 / 확인 필요 / 실행 불가`로 계산한다.

- 영업 종료·접근 통제·예약 불가·노선 없음·사용자 도보 제한 위반이 확인되면 `실행 불가`다.
- 예약 필요인데 예약 준비 상태가 미확인, 운영시간 미확인, 신분증 조건 미확인, 날씨/교통 미검증이면 `확인 필요`다.
- **안전권은 시간 45분 이상이면서 필요한 실행 조건에 미확인·불가가 없는 경우만** 표시한다. 이때도 거리 기반 추정 안내를 함께 둔다.
- 시간은 충분하지만 조건을 모르는 경우 `확인 필요 · 추정 여유 +N분`으로 표시하며 초록색 안전권 색상을 사용하지 않는다.
- 시간 부족과 실행 불가가 겹치면 “오늘 비추천”을 대표 상태로, 모든 원인을 펼침 패널에 남긴다. 한 가지 이유를 해결했다고 나머지가 자동 해제되지 않는다.
- “예약 필요”는 장소 특성이고 “예약 준비 완료”는 사용자의 자기 확인이다. 시설 측 실시간 확인으로 가장하지 않는다.
- `opening_status=unknown`이거나 오래된 운영정보는 평가 당일의 영업 확정으로 사용하지 않는다. 갱신 필요 정책은 소스·필드별로 정하고 단일 날짜만으로 모든 값의 신뢰도를 같게 만들지 않는다.

## 7. 미션 생성과 대안

초기에는 확인한 2~4개 장소의 편집 템플릿을 기반으로 조건을 계산한다. 템플릿의 고정 점수나 예시 여유시간을 실제 결과로 출력하지 않는다. 동일한 엔진이 모든 권역과 카드에 적용된다.

후보 처리 순서는 권역·공개 거점 검증 → 장소 데이터 검증 → 방문 제약 판정 → 시간 계산 → 가족 조건 판정 → 대안 생성 → 정렬이다. 정렬은 실행 가능한 후보, 조건 확인이 필요한 후보, 비추천 후보로 나누고 각 그룹에서 여유시간·가족 적합도·지역 서사·음식/회복 연계 근거를 사용한다.

불가능한 미션을 조용히 숨기지 않는다. 사용자가 선택했거나 처음 요청한 미션에는 원인을 보이고 다음 중 실제로 유효한 대안을 제안한다.

1. 선택 방문 한 곳을 제외해 2개 이상의 장소로 줄인다.
2. 체류시간을 줄일 수 있는 장소만 편집자가 허용한 최소 체류시간까지 줄인다.
3. 미확인/통제된 장소를 같은 권역의 운영조건이 확인된 장소로 바꾼다.
4. 비·눈/강풍 조건이면 실제 실내 장소로 바꾼다. `실내` 태그가 없는 장소를 이름으로 추측하지 않는다.
5. 부모 도보 제한을 충족하는 시설로 바꾸거나 긴 산책 구간을 제외한다.
6. 2개 장소 미션도 성립하지 않으면 “지금은 새 관광 미션을 권하기 어려워요”와 공개 거점 주변의 단일 휴식 선택지를 제공한다. 단일 장소를 2~4개 미션으로 위장하지 않는다.

대안도 같은 엔진으로 재계산한다. 이동수단을 임의로 자차로 바꾸거나 목표시각을 늦춰서 성공시키지 않는다. 사용자가 해당 입력을 바꾸면 별도의 새 평가로 취급한다.

## 8. 설명 가능한 계산 결과

미션 결과에는 생성 시각, 평가 현재시각, 장소·출처 ID, 원본 확인일, 추정 방식 버전, 적용 기본값, 각 구간 시간, 조건 목록, 가족 도보 근거, 날씨 모드, 판정 원인 코드를 포함한다. 민감한 개인 계획 데이터는 디버그 화면에서 통째로 노출하지 않는다.

제품에서 쓸 원인 예시는 다음과 같다.

- “공개 거점까지 추정 여유 52분 · 직선거리 기반 이동 추정”
- “예약 준비를 확인하면 미션을 확정할 수 있어요”
- “대중교통 운행을 확인하지 못해 복귀 가능 여부를 확정하지 않았어요”
- “부모님 도보 제한 20분보다 이 장소의 연속 보행 추정 35분이 길어요”
- “비 시뮬레이션으로 야외 체류와 이동에 24분을 추가했어요”
- “목표보다 12분 늦을 것으로 추정돼요. 가까운 2곳 미션은 여유 28분이에요”

## 9. 공유 allowlist와 개인정보 경계

민감정보가 포함된 원본에서 알려진 키만 지우는 방식보다 **공유 목적별 허용 필드만 새 객체로 구성**한다. 화면만 숨기고 네트워크 응답이나 local demo 공유 객체에 값을 남기지 않는다.

| 범위 | 허용 내용 | 항상 제외 |
| --- | --- | --- |
| 공개 공유 카드 | 고정 서비스 문구, 미션의 공개 제목, 강원 권역/장, 스탬프 종류, 공개 장소를 특정하지 않는 성취 문구 | 정확한 날짜·시간·좌표, 목표시각, 이동 경로, 부대 정보, 군번·실명, 초대코드, 내부 사용자/기기 ID |
| 가족 패스포트 보기 | 허용된 장, 스탬프 종류·개수, 기록 월, 공개 미션 제목 | 정확한 획득 시각·위치, 비공개 메모, 목표시각 |
| 가족 일정 범위 보기 | 선택한 날짜, 권역, 관광 장소의 공개 이름, 공개 만남 거점 이름, 미션 순서 | 분 단위 타임라인, 정확한 좌표, 목표시각, 전체 이동경로, 거점 이후 경로 |
| 식사 선호 보기 | 소유자가 공유에 동의한 선호 범주 | 부대 식단·알레르기·개인 메모의 자동 공유 |
| 미션 제안 | 허용된 공개 미션 ID와 정형 제안 사유 | 자유입력 군 정보, 원래 일정의 강제 변경 |
| 동행 스탬프 | 동의한 동일 미션의 동행 기록 | 공적 방문 인증·군 보상 인증으로 표현하는 값 |

초기 공개 카드에는 자유 텍스트 입력을 두지 않는다. 가족 내부 일정 권한과 외부 이미지 공유를 다른 projection으로 만든다. 가족 권한이 있어도 공개 카드에 상세 장소·날짜를 자동 추가하지 않는다. 공개 관광 장소의 좌표를 앱 지도에 표시하는 것과 사용자의 실제 위치 좌표를 수집하는 것은 구분한다.

## 10. local-demo 초대·권한·해제

1차 시연용 가족 연결은 **“이 기기에서 체험하는 가족 공유 데모”**로 표시한다. 브라우저 로컬 저장소만으로는 다른 기기 간 신원 확인이나 실제 접근 제어를 보장하지 못한다. 같은 브라우저의 역할 전환을 실제 원격 가족 연결로 표현하지 않는다.

- 장병 역할의 소유자가 초대코드를 생성하고 권한을 선택한다. 생성 직후 권한 목록·만료 시각·데모 범위를 보여준다.
- 코드는 예측 가능한 순번 대신 무작위 값으로 설계하고, 초기 정책은 24시간 만료·1회 수락을 제안한다. 구현 시 앱이 제공하는 암호학적 난수 기능을 사용한다.
- 부모 역할에서는 잘못된 코드, 만료, 이미 사용됨, 해제됨을 검증한다. 오류 메시지에 소유자 정보나 코드 유효성 외 개인정보를 노출하지 않는다.
- 초대 수락 후 복사된 권한을 영구 신뢰하지 않는다. 모든 읽기·제안·스탬프 동작에서 현재 연결의 권한·만료/해제 상태를 재검사한다.
- 읽기 권한을 해제하면 관련 화면과 저장된 공유 projection을 즉시 비운다. 여러 탭에서 저장소 변경 이벤트를 받아 열린 화면도 갱신한다.
- 재발급은 기존 초대코드를 무효화한다. 기존 가족 연결도 끊을 것인지는 별도 제어로 분리해 사용자가 무엇을 해제했는지 확인할 수 있게 한다.
- 가족 연결 해제는 이후 접근·제안·동행 스탬프 추가를 중단한다. 과거에 사용자가 내려받은 이미지까지 회수되는 것처럼 표현하지 않는다.
- 부모에게 미션 제안 권한이 있어도 자녀의 원래 미션을 직접 바꿀 수 없다. 자녀가 수락할 때만 새 계획으로 적용하고 현재시각으로 다시 계산한다.
- 데모 리셋은 현재 브라우저의 여행 기록·초대·가족 연결만 삭제하고 그 범위를 미리 표시한다.
- 향후 서버 공유로 전환할 때는 서버에서 사용자·연결·권한을 검증하고 동일한 allowlist를 적용한다. local-demo 제약을 서버 보안 설계로 그대로 가져가지 않는다.

등급은 초 단위 실제값으로 결정하고 표시 분은 양수는 내림, 음수 초과량은 올림해 보수적으로 표현한다. 예컨대 실제 여유 44분59초를 “+45분·안전권”으로 표시하지 않는다. 정렬과 상세 화면이 같은 결과 객체를 사용해 등급·숫자가 서로 다르게 보이지 않도록 한다.

## 12. 완료 기준

- 동일 입력·시계·데이터 버전이면 같은 미션과 산식 결과가 나온다.
- 입력 변경·시간 경과·권한 해제가 화면에 실제로 반영된다.
- 확실한 데이터, 추정값, 사용자 확인, 시연값, 미확인 값이 구분된다.
- 2~4개 관광 장소를 묶은 미션이 성립하지 않으면 그 이유를 설명하고 가능한 수준의 대안을 제공한다.
- 공개 공유 결과에서 민감정보가 구조적으로 제외된다.
- 실제 경로 검증 전 거리 추정이 군 복귀 보증으로 읽히지 않도록 공개 거점 범위와 계산 한계를 계속 표시한다.
