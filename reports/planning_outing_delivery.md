# 즐겨찾기·여행 계획·현재 출타 구현과 검증

2026-09-08. **① 웹·앱 개발 부문**, 강원 지역특화 서비스. [이슈 #9](https://github.com/MySonIsSoldier/gunbeon-yeojido/issues/9)와 [PR #10](https://github.com/MySonIsSoldier/gunbeon-yeojido/pull/10)에서 관리한다. 사용자 후속 요청에 따라 초기 공개 민간 장소 제한을 변경했다. 아래는 구현·실행한 검증 결과이며, 현장 방문이나 실제 사용자 조사 결과가 아니다.

## 확정한 사용자 경험

| 진입 | 구현한 흐름 |
|---|---|
| 만남 장소 | 즐겨찾기 목록 → 선택, 즐겨찾기 추가하기 또는 직접 설정하기 → 지도 위치·이름 지정. 가까운 후보·관광정보 검색은 이 선택창에 표시하지 않는다. 공개 민간 장소 선언 체크를 제거했다. |
| 일정에 장소 추가 | 즐겨찾기를 맨 먼저 표시하고 기존 가까운 후보·TourAPI 검색·직접 장소 입력·지도 선택을 유지한다. |
| 내 여행 | 만남 장소와 방문 장소가 없는 빈 코스도 저장·새로고침·재편집할 수 있다. 채우기 전에는 안전권 수치를 만들거나 출타·방문 완료를 허용하지 않는다. 장소는 최대 12곳이다. |
| 둘러보기·지도/미션 | 출발 예정 날짜·시각과 정한 시간창을 기준으로 비교한다. 현재 시각이 흘러도 계획 마진·도착 예정 시간이 자동으로 줄거나 이동하지 않는다. 예보의 수신 유효기간은 실제 시각으로 검사한다. |
| 현재 출타 | 계획 선택 → 오늘 돌아올 시각 확인 → 출타 시작. 실제 시작·남은 시간, 마지막으로 확인한 장소부터의 잔여 일정, 현재 날씨 보정을 표시한다. 장소 진행·되돌리기·새로고침 복원·시계만 종료를 제공한다. |
| 여행 완료 | 여행 완료 → “여행, 잘 다녀오셨나요?” 확인창에서 스탬프 선택 → 여행 완료로 기록. 취소하면 계획·출타·스탬프가 변하지 않는다. 휴가 씨앗은 별도 준비 기록이다. |

하단 메뉴는 둘러보기 / 지도·미션 / 현재 출타 / 가족 / 내 여행이다. 계획의 날짜와 실제 출타 시작 상태를 별도로 보관한다. 진행 중인 코스는 중앙 편집 진입점에서도 잠가 저장 계획을 수정하다 현재 출타가 덮어써지는 일을 막는다. 새 코스를 계획하는 기능은 계속 사용할 수 있다. 출타 시계는 한 개만 진행한다.

## 저장과 공유

개인 장소는 정문 앞이나 늘 만나는 장소 등 사용자가 직접 선택한다. 이름·설명·선택 좌표를 브라우저 localStorage의 즐겨찾기와 코스에 보관하며 공공 관광지로 분류하거나 방문 가능성을 검증했다고 표시하지 않는다. 즐겨찾기 수정·삭제가 기존 여행의 장소를 바꾸지 않도록 선택 당시 값을 코스에 보존한다.

계획에는 출발 예정 시각과 시간창, 이동수단, 장소 순서·체류시간을 저장한다. 현재 출타에는 시작 시각·시간창·장소 진행·날씨 보정을 별도로 저장한다. 따라서 종료 기준은 저장 값에서 재구성할 수 있다. 과거 문서의 “복귀 기준을 저장하지 않는다”는 설명은 이 버전에 적용하지 않는다. 이전 저장 버전은 읽을 수 있으며 시간창이 없는 구형 계획은 4시간 기본값을 안내한다.

가족 투영·공개 카드에는 개인 장소명·설명·좌표·자유 코스명·정확한 시각·상세 경로를 넣지 않는다. 서버 계정·기기 간 동기화는 없다. 브라우저 데이터를 지우면 로컬 계획과 기록도 사라진다. 지도 SDK·사용자가 여는 외부 길찾기는 제공자의 통신을 사용하므로 모든 좌표가 기기를 벗어나지 않는다고 표현하지 않는다. GPS 자동 수집, 군번·작전·근무정보·휴가증·군 신분증 이미지 입력 기능은 없다.

## 수정 과정에서 발견하고 해결한 결함

- 계획 날짜를 서버 렌더링 시각으로 표시하면 테스트 시계 이동 뒤 새로고침에서 hydration 불일치가 발생했다. 로컬 상태를 불러온 후 계획 날짜를 표시하도록 수정하고 재검사했다.
- 저장한 일반 추천 미션에서 날짜·수단을 바꿔도 과거 계획 조건이 덮어쓰던 문제를 수정했다.
- 내 여행 목록에서는 막았던 진행 중 코스 편집이 상단 진입점으로 가능했던 문제를 중앙 가드로 보완했다.
- 현재 출타에 날씨 조건이 전달되지 않던 문제를 수정했다. 직접 적용한 눈·비·강풍과 예보 만료를 현재 계산에 반영한다.
- 새로고침 직후 코스를 열 때 공공 장소 목록이 도착하기 전에 조회 실패로 보이던 상태를 `ede91d3`에서 로딩 안내로 수정했다. 목록 응답을 의도적으로 지연하는 브라우저 회귀 검사를 추가했고 장소 복원이 끝난 뒤 증빙 화면을 촬영하도록 보완했다.
- 버전8 공개 검사에서 Edge360px 지도 초기화가 25초 대기를 넘겼고 동일 환경 재검사도 실패했다. 지도 키보다 기준 장소 좌표가 늦게 도착할 때 초기화 effect가 재실행되지 않는 결함을 확인했다. `c075e13`에서 좌표 변경을 초기화 의존성에 추가하고, 키 조회는 정상으로 둔 채 장소 목록 두 응답을 늦추는 실제 지도 검사를 추가했다.
- 개인 즐겨찾기보다 저장 코스의 장소 스냅샷을 우선하고, 계획 시각과 예보의 실제 유효기간을 구분했다.

브라우저 시계를 제어해 계획 상태에서 30분, 출타 상태에서 10분을 진행하고 값의 고정·감소를 비교했다. 실제 이동·복귀를 측정한 결과가 아니다. 별도 테스트 프로필에서 가상의 개인 장소·여행 날짜를 사용했으며 사용자의 실제 여행 기록을 수정하지 않았다.

모바일 검사는 데스크톱 Chrome·Edge에서 화면 크기·터치를 에뮬레이션한 것이다. 실물 Android/iPhone, iOS Safari, 부모·장병 참여자 사용성은 미검증이다. 저장 장소 수·공식 출입·접근성·교통 지연의 현장 정확도를 증명하는 검사도 아니다.

공개 브라우저 검사에서 기존 흐름이 요청한 서비스 API 수는 결과 JSON에 경로별로 남겼다. 실제 제공기관 호출 횟수나 전체 테스트 합계와 같지 않다. 요청 원문·API 키·쿠키는 증빙에 보관하지 않는다. 새 `test:outing`은 기존 `test:browser`, `test:custom`과 함께 GitHub의 키 없는 브라우저 CI에 포함했다.

## 공개 버전과 재현

[외부 테스트 사이트](https://gunbeon-yeojido-gangwon.ybuser.chatgpt.site/)의 기존 임시 비밀번호 입장을 유지한다. 현재 버전9, 배포 소스 `e6c6fcf094c21ea443dce7b4d736522f43ef2764`, 배포 `appgdep_6a9f60b48c3481919b0ce39044941b41`, 2026-09-08 10:11(KST) succeeded. 앞선 버전7의 배포 소스는 `1a9dd5c02c422424aeaf182195c2c98f65c4e09b`이며 검사 결과를 버전별로 구분했다. 런타임 secret revision2 유지. [배포 기록](deployment.md).

```sh
cd web
npm run typecheck
npm test
npm run build
npm run test:outing
# 공개 URL, 설치된 Chrome/Edge, 두 화면 크기로 재현
QA_BASE_URL=https://gunbeon-yeojido-gangwon.ybuser.chatgpt.site \
QA_BROWSER_CHANNELS=chrome,msedge QA_CASES=small,desktop npm run test:outing
```

Edge가 기본 위치에 없다면 `QA_EDGE_EXECUTABLE`에 설치 실행 파일 경로를 지정한다. API 키는 서버 환경변수로만 사용한다. 키 없는 CI는 `QA_LIVE=0`을 사용하며 실제 API 성공 검사와 구분한다.
