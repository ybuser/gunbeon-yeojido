# 직접 만드는 여행안 — 트리플 벤치마크와 최소 완결 UX

> 버전6까지의 설계·구현 이력입니다. 2026-09-08 버전7에서 공개 장소 확인 체크를 제거하고 개인 장소·즐겨찾기, 빈 코스 저장, 계획/현재 출타 분리와 시간창 보관을 적용했습니다. 현재 동작과 저장 범위는 [최신 구현·검증](planning_outing_delivery.md)을 기준으로 합니다.

확인일: 2026-09-07. ① 웹·앱 개발 부문의 강원 지역특화 모바일 웹을 기준으로 작성했다. 공식 공개 자료에서 확인한 비교 서비스의 기능과 군번여지도에 대한 설계 제안을 분리한다. 이 문서는 구현·로그인 테스트·실기기 QA 완료 보고서가 아니다.

## 1. 공식 자료에서 확인한 트리플의 흐름

| 관찰 대상 | 공식 자료가 설명하는 기능 | 군번여지도에 적용할 원칙 |
| --- | --- | --- |
| 추천을 시작점으로 편집 | 취향에 따라 추천받은 일정을 내 일정으로 저장한 뒤 장소를 추가하거나 제외한다. [트리플 공식 소개 글, 2024.06](https://triple.guide/articles/f9ee0b66-0f41-40b6-8c2f-46ed2ae12fe1) | 추천 카드의 끝을 저장으로 닫지 않고, `가져와서 수정`으로 내 여행 편집기에 연결한다. |
| 일정과 지도 연결 | 공식 사용법은 지도를 보며 일정을 계획하고, 일정의 장소 사이 거리 표시에서 길찾기를 여는 흐름을 소개한다. [트리플 공식 사용법, 2023.01](https://triple.guide/articles/8e26647d-9e7b-4346-8517-4945ced97bb8) | 장소 목록과 지도 핀의 번호·순서를 일치시키고, 이동 구간의 추정값과 외부 길찾기를 나란히 제공한다. |
| 공유 목적 구분 | 초대 링크로 함께 보고 편집하는 기능과, 일정 링크를 전달해 보여주는 기능을 별도로 설명한다. [트리플 공식 사용법](https://triple.guide/articles/8e26647d-9e7b-4346-8517-4945ced97bb8) | 가족의 `보기`, `제안`, 소유자의 `적용` 권한을 구분한다. 현재 같은 브라우저 체험을 실제 기기 간 공동편집으로 표현하지 않는다. |
| 장소·시간·메모를 한 일정에 배치 | 공식 활용 글의 화면 설명에는 일정표에 장소 추가, 시간대별 정리, 방문 순서에 따른 지도 표시, 장소 메모가 나온다. [트리플 공식 활용 글, 2025.04](https://triple.guide/articles/7ef0287a-1fae-4e96-b806-cc6720d75584) | 편집의 중심은 번호가 있는 장소 목록이다. 체류시간과 이동 추정을 그 안에서 수정·확인하도록 한다. 자유 메모의 범위는 군번여지도의 미수집 원칙에 맞춰 제한한다. |
| 여행 맥락 안에서 추천 | 날짜·도시·동행·여행 스타일에 따라 정보를 추천하고, 마음에 드는 정보를 일정에 담는 구조를 소개한다. [트리플 여행홈 개편 설명, 2024.07](https://triple.guide/articles/780472d8-828d-4657-bdd8-b7ac5e5e7b6c) | 장소 추가 화면에 현재 권역·공개 거점·동행 조건을 유지한다. 사용자가 지역을 다시 입력하지 않게 한다. |
| 여행 전과 도중의 수정 | 현재 공식 소개 페이지는 계획한 일정을 여행 전·여행 중에 수정하고 다시 확인하는 경험을 설명한다. [트리플 공식 소개](https://triple.guide/intro) | 저장한 여행안은 다시 열어 편집할 수 있어야 하며, 실시간 추천 결과 변화가 저장한 장소를 바꾸면 안 된다. |

위 자료는 공개 설명과 화면 캡션에 대한 관찰이다. 현재 앱에서 직접 조작한 결과는 아니다. 장소 순서를 드래그하는 정확한 제스처, 직접 입력 장소의 등록 절차, 저장 시점의 현재 동작은 이번 공식 자료로 확정하지 않았다. 검색된 `여행 도구 순서 변경` FAQ는 도구 메뉴 정렬에 대한 내용이므로 장소 순서 편집의 근거로 사용하지 않았다. 아래 버튼·배치·수치 기준은 군번여지도용 설계 제안이다.

## 2. 최소 완결 경험

**내 여행 → 새 코스 만들기 / 기존 코스 가져오기 → 장소·순서·체류시간 편집 → 복귀 여유 재확인 → 저장 → 다시 열기 → 가족에게 제안**을 하나의 흐름으로 연결한다. 사진 타일은 이 여행안을 알아보는 표지이며, 편집과 저장의 일관성이 먼저다.

### 진입과 편집 화면

1. `내 여행` 상단에 `새 코스 만들기`를 주 버튼, `기존 코스 가져오기`를 보조 버튼으로 둔다. 빈 목록에서도 두 동작을 제공한다. 추천 상세에도 `가져와서 수정`을 둔다.
2. 새 코스는 현재 선택 권역과 공개 만남 거점을 기본값으로 받는다. 코스명은 `철원에서 보내는 우리 하루`처럼 자동 생성하고 수정 가능하게 한다. 실제 부대·군번·복귀 정보 입력란은 만들지 않는다.
3. 가져오기는 현재 추천 코스 또는 내 저장 코스를 고른 뒤 **새 여행 ID의 사본**을 만든다. 원본과 기존 방문 스탬프는 바꾸지 않는다. 기존의 미방문 계획에서 `수정`으로 들어온 경우에만 그 계획을 갱신한다.
4. 편집 화면은 공개 만남 거점, 번호가 붙은 장소 목록, `장소 추가`, 하단 고정 `변경사항 저장`으로 구성한다. 장소마다 작은 사진·이름·출처·체류시간·`위로/아래로`·`삭제`를 제공한다. 드래그는 있더라도 버튼을 대체하지 않는다.
5. 편집 중 변경은 임시 상태에 적용하고 저장 시 한 번에 반영한다. `닫기`는 저장 전 변경이 있을 때 `계속 편집 / 변경 버리기`를 보여준다. 저장 후 내 여행 카드와 상세를 같은 기록 ID로 갱신한다.
6. 방문 기록이 있는 여행은 `복사해서 새 계획 만들기`를 우선 제공한다. 과거 여행의 장소를 바꾸면서 기존 스탬프를 그대로 이어받는 동작은 막는다.

모바일에서는 긴 전체 화면 편집기 하나를 사용하고 장소 찾기는 그 위의 검색 화면으로 연다. 검색 후 선택한 장소를 추가하면 원래 목록의 스크롤과 수정값으로 돌아온다. 편집기를 중첩된 여러 바텀시트로 쌓지 않는다.

### 장소 추가: 검색·추천·직접 입력·지도 선택

| 진입 | 최소 동작 | 완료·실패 상태 |
| --- | --- | --- |
| TourAPI 검색 | 현재 권역을 유지하고 관광지·문화시설·음식점 등 유형을 선택한다. 장소명 검색 결과에 사진·주소의 시군·유형·출처와 `추가`를 보여준다. | 로딩, 결과 없음, API 실패를 별도로 보여준다. 실패를 검색 결과 0건으로 처리하지 않는다. |
| TourAPI 추천 | 공개 거점 또는 마지막 장소 주변 후보에서 이미 담은 장소를 제외한다. `마지막 장소에서 가까운 문화시설`처럼 실제 사용한 조건을 한 줄로 밝힌다. | 좌표·운영·접근 정보의 결측을 숨기지 않는다. 식사 선호나 무장애 적합성이 미검증이면 맞춤 추천으로 단정하지 않는다. |
| 직접 입력 | `공개 장소 이름`과 유형을 받는다. 일치하는 공공 POI가 있으면 연결을 제안하되 강제 자동 대체하지 않는다. 미연결 항목도 `직접 입력 · 위치 확인 필요` 상태로 초안에 유지할 수 있게 한다. | 직접 입력은 TourAPI 검증 장소와 구분한다. 좌표가 없으면 구간 이동시간과 전체 복귀 여유는 미계산으로 남긴다. 이름만으로 공개 출입·예약·보상·무장애 적합성을 만들지 않는다. |
| 지도에서 선택 | 지도에서 공공 관광 POI 또는 공개 민간 거점을 고르고 장소명·유형을 확인한 뒤 추가한다. 임의 지점 선택 시 주변 공개 장소 후보를 제시하고 확인을 거친다. | POI로 확인하지 못한 지점은 `위치 확인 필요` 초안으로 유지한다. 정확한 임의 좌표를 자동 저장하거나 일반 공개 관광지로 판정하지 않는다. 지도 SDK 실패 시 검색·직접 입력으로 돌아갈 수 있다. |

지역은 접경 5군과 춘천·속초 관문으로 제한한다. 직접 입력의 빈 결과를 다른 지역의 동명 장소로 채우지 않는다. 동일 POI를 다시 추가할 때는 기존 항목 위치를 알려준다. 공개 거점으로 돌아오는 마지막 구간은 자동 표시해 관광 장소 목록에 같은 거점을 중복 추가할 필요가 없게 한다.

사진 1~4장 요청과 장소 수 제한은 별개다. 기존 추천 미션의 2~4개 장소 기준은 유지하되, 빈 코스와 장소 한 개짜리는 편집·임시 저장이 가능해야 한다. 완성된 미션과 준비 중 초안을 구분한다. 기존 2~4개 복원 검사 때문에 한 개짜리 초안을 저장 후 열지 못하는 회귀가 생기지 않게 한다.

### 시간 수정과 복귀시계

- 저장하는 시간은 장소별 체류 분과 필요한 상대 순서다. 체류시간은 숫자 입력과 짧은 선택값을 함께 제공하고 0·음수·NaN·비현실적인 초과값을 검증한다. 최소 UI 범위는 5~240분을 제안하며 관광지 기본값을 사용자가 바꿀 수 있게 한다.
- 정확한 시작·복귀 기준시각은 이번 세션의 계산 설정으로 둔다. 시각을 바꾸면 일정표의 표시 시각을 재계산하지만 기존 미수집 원칙에 따라 복귀시각은 저장·가족 공유하지 않는다. 저장 후 안내는 `장소·순서·체류시간을 저장했어요. 시작·복귀시각은 다시 정해주세요.`처럼 구체적으로 쓴다.
- 장소 추가·제거·순서·체류·공개 거점·이동수단이 바뀔 때 같은 초안에서 이동 추정과 안전마진을 다시 계산한다. 지도와 사진의 번호도 같은 배열을 사용한다. 사용자가 고른 순서를 추천 엔진이 다시 정렬하지 않는다.
- 순서 변경으로 30분 이상 더 걸리면 늘어난 추정 이동시간과 조정 버튼을 보여준다. 이 수치는 UX 알림 기준 제안이며 교통 정확도 보장이 아니다. 시간이 부족한 코스도 숨기지 않고 `한 장소 줄이기 / 체류시간 줄이기 / 목표시각 확인`을 제공한다.
- 위치가 미확인인 장소가 하나라도 있으면 전체 이동을 0분으로 더하지 않는다. `이동시간 미확인 · 복귀 여유 계산 전`을 표시하고, 계산 가능한 체류 합계와 누락 구간을 따로 보여준다.
- 현재 예보 범위 밖 날짜·시간에는 해당 여행의 예보를 확인한 것처럼 표시하지 않는다. 1박 일정은 날짜가 있는 초안으로 유지하며 숙소·막차·다음 날 예보까지 검증한 확정 일정으로 표현하지 않는다.

## 3. 사진 1~4장 타일

아래는 트리플의 배치라고 주장하는 것이 아니라 사용자 요청에 맞춘 군번여지도 제안이다. 코스 카드·내 여행·가져오기 미리보기에서 같은 타일 규칙을 사용한다.

| 사용할 수 있는 실제 장소 사진 수 | 배열 | 표시 원칙 |
| --- | --- | --- |
| 1 | 한 장을 전체 폭으로 | 그 사진의 장소명을 표시한다. 코스 전체의 모든 장소 사진인 것처럼 표현하지 않는다. |
| 2 | 같은 크기의 좌우 2장 | 방문 순서에 맞춰 배치하고 각 타일에 원래 장소 번호를 붙인다. |
| 3 | 왼쪽 큰 1장 + 오른쪽 위아래 2장 | 큰 사진도 첫 사진일 뿐 대표 명소 적합성이나 인기를 의미하지 않는다. |
| 4 | 같은 크기의 2×2 | 장소 순서대로 읽히게 하고 각 사진의 장소명·번호를 유지한다. |
| 0 | 중립 배경 + 장소 이름 목록 | `사진 준비 중` 또는 `직접 입력 장소`로 표시한다. 지역 풍경·다른 시설 사진을 해당 코스 장소처럼 대체하지 않는다. |

합성 타일 영역은 일정한 가로세로 비율을 유지해 목록이 흔들리지 않게 한다. 이미지는 확인된 장소 ID에 연결된 대표 사진만 사용하고 동일 URL의 반복을 제거한다. 사진이 없는 장소를 제외해 세 장이 되었다면 번호는 1·3·4처럼 **실제 일정 번호**를 유지한다. 사진 수와 별도로 `장소 4곳`을 표시한다. 실패한 이미지 한 장 때문에 코스 전체를 빈 상태로 만들지 않는다. 대체 텍스트는 실제 장소명으로 작성하고 출처는 상세에서 확인할 수 있게 한다. 사진 업로드·EXIF 수집은 이번 요청의 최소 구현에 필요하지 않다.

## 4. 저장 계약과 민감정보 경계

현재 확인한 `Entry.plan`은 공개 거점 ID와 장소별 `placeId/stay/walk`를 보존하며 `resolveEntry`는 모든 참조를 찾을 수 있는 2~4개 장소만 복원한다. 직접 입력 장소를 추가할 때 임시 Place 객체만 화면에 붙이면 새로고침 후 사라질 수 있다. 최소한 공공 데이터 참조와 사용자 입력 초안을 구분하는 저장 형식이 필요하다. 이는 구조 제안이며 코드 변경 결과가 아니다.

| 대상 | 허용 범위 | 제외·미확인 처리 |
| --- | --- | --- |
| TourAPI 장소 | 공급자·공개 장소 참조 ID·사용자 순서·체류 분. 표시 자료는 기존 재조회 방식 유지. | 공급자 원문·상세·이미지 전체를 저장하는 방식으로 확장하지 않는다. 재조회 실패는 해당 항목의 오류로 남겨 다른 장소로 대체하지 않는다. |
| 직접 입력 장소 | 최소 공개 장소명·유형·시군·사용자 입력 출처·확인 상태. 검증된 POI와 연결되면 그 참조 ID 사용. | 자유 주소·실명·전화번호·정확한 복무지·임의 좌표·긴 자유 메모는 받지 않는다. 미연결 항목은 계산·공유 가능 범위가 제한된 초안이다. |
| 군 관련 정보 | 공공 관광시설의 공식 이름과 공개 관광 정보만 사용. | 실제 부대명·군번·근무/작전·휴가증·군 신분증·복귀경로 입력을 유도하는 필드를 두지 않는다. |
| 가족 보기 | 권한이 있을 때 확인된 공개 장소 이름·순서, 자동 생성한 일반 여행 제목. 제안은 별도 사본이며 적용은 명시적 동작. | 직접 쓴 제목·메모·미확인 장소명을 그대로 투영하지 않는다. 정확한 시간·좌표·복귀 정보는 제외한다. |
| 공개 공유 카드 | 시군·검증된 일반 미션명·허용 스탬프·일반 문구. | 사용자 자유 제목을 그대로 출력하는 기존 경로는 새 입력 기능과 함께 재검토한다. 가족 일정 권한과 공개 카드 범위를 동일하게 만들지 않는다. |

직접 입력과 검색 전에는 `공개 관광 장소만 입력하세요. 부대·군번·복무지 정보는 입력하지 마세요.`를 가까이 배치한다. 제한된 길이·유형 선택과 민감정보 패턴 검사를 입력 시점과 저장 경계에 적용하고, 거부된 원문을 로그·분석·외부 검색으로 보내지 않는다. 키워드 검사만으로 모든 민감정보나 공개 출입 여부를 판정할 수는 없다. 공식 관광 POI 참조를 우선하는 구조가 기본 경계이며, 공공 박물관·현충시설 이름의 군 관련 단어는 검증된 ID에 한해서 처리해 무차별 차단을 피한다.

현재 `publicCard`의 `entry.title` 출력과 가족 일정의 장소명 투영에 자유 입력이 연결되면 공유 경계가 달라진다. 공유 직전에 허용 필드로 새 객체를 만들고, 자동 일반 제목 및 검증된 장소명만 사용해야 한다. 내 초안에 저장할 수 있다는 사실이 공개 공유 허용을 의미하지 않는다.

## 5. 이번 기능 우선순위

| 순서 | 이번 요청의 필수 범위 | 완료 기준 |
| --- | --- | --- |
| P0-1 | 공개 체험 로그인과 기존 접근 흐름 | 비밀번호 `1234`로 진입, 오입력·재진입·로그아웃 동작을 실제 배포에서 확인한다. 공개 체험 비밀번호를 가족 초대 권한·개인 계정 인증·기기 동기화로 설명하지 않는다. |
| P0-2 | 내 여행에서 생성·가져오기·수정 | 원본 사본과 기존 계획 수정이 구분되고 장소·순서·체류 분이 새로고침 후 유지된다. 저장 취소는 원본에 영향이 없다. |
| P0-3 | TourAPI 검색·추천 및 직접 입력·지도 선택 | 네 진입 방법이 같은 편집 배열로 연결된다. 직접 입력과 위치 미확인도 다시 열 수 있고, 미확인을 안전권으로 계산하지 않는다. |
| P0-4 | 1~4 사진 타일과 편집 재계산 | 실제 장소 사진·번호가 코스 순서와 일치한다. 장소 교체 시 사진·지도·안전마진·내 여행 카드가 함께 갱신된다. |

## 6. 구현 후 반드시 실행할 확인 사례

1. 새 코스를 만들고 TourAPI 장소 두 곳을 추가해 체류시간·순서를 바꾼다. 저장·새로고침·다시 열기에서 같은 항목과 시간이 유지되어야 한다.
2. 추천 코스를 가져와 한 장소를 직접 입력 항목으로 바꾼다. 원본은 유지되고 사본에는 미확인 상태가 남아야 한다. 미확인 항목을 공개 POI로 연결하면 이동 계산이 재개되어야 한다.
3. 지도에서 공개 관광지를 선택한 뒤 목록으로 돌아온다. 번호·사진·장소명·추정 구간이 일치해야 한다. 빈 지도, SDK 실패, 검색 API 실패에서도 초안은 보존되어야 한다.
4. 같은 장소 재추가, 0·1개짜리 초안, 삭제 후 되돌아가기, 저장 전 취소, 조회 중 연속 검색, 빠른 지역 변경을 확인한다. 이전 검색 응답이 새 권역 목록에 들어오면 안 된다.
5. 사진 0·1·2·3·4개와 일부 로딩 실패를 확인한다. 타일의 장소명이 사진의 출처 ID와 같고, 사진이 없는 장소도 일정 목록에는 남아야 한다.
6. 체류시간을 늘려 여유가 음수가 되는 경우와 위치 미확인인 경우를 나누어 확인한다. 각각 시간 부족과 미계산으로 표시되어야 한다.
7. 자유 제목·미확인 장소가 포함된 초안을 가족에게 제안하거나 공유 카드로 만들 때 허용되지 않은 원문이 노출되지 않아야 한다. 권한 해제 후 제안·보기의 기존 제한이 유지되어야 한다.
8. 공개 체험 비밀번호로 별도 브라우저에 들어가도 로컬 여행이 자동 동기화된다고 표시하지 않아야 한다. 실제 확인 환경과 아직 확보하지 못한 실기기를 [브라우저 QA 보고서](browser_qa_report.md)에 구분한다.

개발에서 가장 먼저 닫아야 할 고리는 사진 배치 자체보다 **사용자가 고친 배열이 저장·지도·사진·복귀 계산·가족 제안에서 같은 배열로 남는 것**이다. 공공데이터는 검색 재료에 그치지 않고 장소의 위치·관광 분류·접근 정보와 미확인 조건을 설명하는 근거로 계속 드러나야 한다.

## 7. 구현에서 확정한 선택 — 2026-09-08

위 표는 초기 제안이다. 실제 사용자 요청과 편집 흐름을 검토하여 다음과 같이 확정했다.

- 1~12곳을 한 코스로 저장한다. 코스마다 처음 네 **장소**를 표지에 사용하고, 사진이 없는 장소는 이름과 번호를 남긴다. 사진 URL이 같아도 다른 장소를 지우지 않는다.
- 출발 날짜·시각과 이동수단은 이 브라우저의 개인 계획에 보관한다. 복귀 기준시각은 저장·공유에서 제외한다. 장소별 도착·출발은 체류시간과 거리 추정으로 함께 계산한다.
- 직접 입력은 공개 장소명·공개 주소·유형·권역·선택한 공개 위치로 제한한다. 지도 선택은 위치 미검증 상태이며, 공개 장소임을 확인해야 저장된다. 좌표가 없어도 장소는 보존하되 전체 복귀 여유를 미계산으로 표시한다. GPS와 개인 주소를 요청하지 않는다.
- TourAPI는 장소 ID를 저장하고 검색·상세 API로 다시 읽는다. 원문 데이터와 이미지는 개인 저장소에 복제하지 않는다. 복원 중에는 로딩 상태를 보여주고, 실패한 장소를 다른 추천으로 바꾸지 않는다.
- 자유 제목과 직접 장소 이름은 공개 공유 카드 및 가족 투영에서 일반 문구로 치환한다. 정규식 검사는 보조 수단이며 모든 민감정보나 실제 공개 출입 가능 여부를 판정한다는 뜻이 아니다.
- 가까운 후보는 공개 거점 또는 마지막 장소와의 직선거리 순이다. 무장애나 식사 선호를 완전히 검증한 개인화 추천으로 표현하지 않는다.
- 다중 날짜 입력·드래그·실시간 공동편집은 다음 단계로 남기고, 날짜를 넘기는 시간 표시·명시적 위아래 이동·저장/취소를 먼저 완성한다.
