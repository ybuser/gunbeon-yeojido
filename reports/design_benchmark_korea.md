# 국내 여행 서비스 벤치마크와 군번여지도 화면 재설계

- 조사일: 2026-09-07
- 대상: 트리플, 마이리얼트립, 네이버지도 공식 소개·공식 앱스토어·공식 고객센터.
- 산출물 성격: 자료 조사와 UX 제안. 웹 코드와 Sites는 수정하지 않았다.
- 관찰 한계: 공개 페이지의 화면 문구·구조와 공식 기능 설명을 확인했다. 연결 가능한 CUA 브라우저가 없어 실제 앱 조작 및 모바일 화면의 픽셀·폰트·버튼 치수는 확인하지 못했다. 일부 앱스토어 직접 조회는 429를 반환했다. 따라서 앱 내부 탭 순서·개인화 첫 화면·정확한 간격을 관찰했다고 주장하지 않는다.
- 표기: **관찰**은 아래 공식 자료에서 확인한 사실, **해석/제안**은 군번여지도에 적용하기 위한 판단이다. 앱스토어 홍보 화면·소개는 실제 사용 흐름 전체의 증거가 아니며, 편집 기사도 사용성 실험 결과가 아니다.

## 1. 결론

군번여지도 첫 화면은 브랜드 설명을 읽는 페이지보다 **“어느 지역에서, 오늘 몇 시간 함께할 수 있는가”를 선택하는 여행 시작 화면**이어야 한다. 권장 흐름은 **지역·시간 선택 → 추천 미션 비교 → 지도·일정 확인 → 내 일정에 저장 → 가족에게 제안·공유 → 여행 후 패스포트 기록**이다.

“복귀시계·부모 브리핑룸·패스포트·휴가회수 레이더”를 같은 무게의 기능 버튼으로 늘어놓으면 사용자가 어떤 순서로 써야 하는지 다시 판단해야 한다. 서비스 고유 이름은 상세 화면·여행 기록에 살리고, 기본 내비게이션과 행동 버튼에는 여행자가 이해할 말을 쓴다. 이는 아래 서비스의 기능 개수를 따라 하려는 것이 아니라 사용자가 다루는 대상인 장소·여정·저장한 일정을 중심으로 구조를 바꾸려는 제안이다.

## 2. 공식 근거와 실제 관찰

### 트리플

**관찰:** 공식 소개는 일정 생성·관리, 여행 전·중 일정 수정, 취향별 추천, 동행자와 함께 계획·수정을 주요 기능으로 설명한다. 일정에 넣은 장소와 관련 가이드·숙소·입장권을 연결해 보여주는 콘텐츠도 확인된다. [트리플 공식 소개](https://triple.guide/intro)

**관찰:** Apple의 공식 앱 소개는 가고 싶은 장소 저장 후 지도에서 동선을 보며 일정을 만들고 동행인과 공유하는 사용법을 설명한다. 개발사 앱스토어 소개도 갈 곳 선택, 동선·일정, 동행인 초대를 연결한다. [Apple 트리플 소개](https://apps.apple.com/kr/iphone/story/id1373051558), [트리플 공식 App Store](https://apps.apple.com/kr/app/%ED%8A%B8%EB%A6%AC%ED%94%8C-%ED%95%AD%EA%B3%B5-%ED%98%B8%ED%85%94-%EC%B5%9C%EC%A0%80%EA%B0%80-%EC%98%88%EC%95%BD-%EC%97%AC%ED%96%89%EA%B3%84%ED%9A%8D/id1225499481)

공식 소개에 연결된 모바일 일정 이미지 원본 URL도 확인했다. 이 조사에서는 원본 이미지의 픽셀을 시각 검증하지 않았으므로 특정 배치·색·폰트의 근거로 사용하지 않는다. [공식 모바일 일정 이미지](https://triple.guide/intro/static/images/itineraries/itinerary_mobile_01%402x.png)

**해석/제안:** 군번여지도의 중심 객체도 여러 기능 화면이 아니라 하나의 저장 가능한 여행 일정으로 둔다. 부모 공유는 완전히 다른 결과물을 만드는 막다른 화면이 아니라 같은 여행안의 허용된 정보를 보고 대안을 제안하는 협업 단계로 연결한다. 일정 밖에서 패스포트·날씨·보상 기능을 각각 시작하게 만드는 흐름을 줄인다.

### 마이리얼트립

**해석/제안:** 군번여지도도 지역을 고른 뒤 지역의 실제 장소 사진과 비교 가능한 수치를 보여주는 편이 좋다. 상품의 가격 위치에 군번여지도의 핵심 비교값인 **총 소요시간·거점 도착 여유**를 둔다. 이 서비스에는 예약 거래가 없으므로 상품 판매 CTA·특가 배너·광고 밀도까지 모방할 이유는 없다. 저장 후에는 사용자가 “내 일정”에서 계획을 다시 찾게 한다.

### 네이버지도

**관찰:** 공식 App Store 설명은 홈의 발견·예약·대중교통·내비게이션·저장 기능, 하나의 통합검색, 지도 위 장소 저장·친구 공유를 명시한다. 장소를 찾은 뒤 길찾기·예약으로 연결하며 저장 목록에서 영업·예약 상태를 확인하는 업데이트도 설명한다. [네이버지도 공식 App Store](https://apps.apple.com/kr/app/%EB%84%A4%EC%9D%B4%EB%B2%84%EC%A7%80%EB%8F%84-%EC%9E%A5%EC%86%8C%EC%9D%98-%EB%B0%9C%EA%B2%AC%EA%B3%BC-%EC%98%88%EC%95%BD-%EB%82%B4%EB%B9%84%EA%B2%8C%EC%9D%B4%EC%85%98/id311867728)

**관찰 한계:** 지도 웹 도메인은 조사 도구에서 robots 제한을 반환했다. 모바일 탭의 정확한 시각 순서나 바텀시트 높이를 직접 확인하지 않았다. 앱스토어 사용자 리뷰는 개별 경험이므로 이번 설계 판단의 증거로 사용하지 않았다.

**해석/제안:** 군번여지도 지도는 장식 배경이 아니라 선택한 미션을 공간적으로 확인하는 화면이어야 한다. 리스트의 장소를 누르면 같은 장소 핀이 선택되고, 지도 핀을 누르면 같은 장소 카드가 열려야 한다. 저장은 별개의 스탬프 획득과 구분한다. 실제 길찾기는 외부 지도에 맡기되 현재 미션과 돌아올 공개 거점을 잃지 않도록 연결한다.

## 3. 비교에서 얻는 구조 원칙

| 비교할 일 | 공식 자료에서 보이는 공통 대상 | 군번여지도 적용 제안 |
| --- | --- | --- |
| 탐색 시작 | 지역·장소·취향·범주 | 첫 화면 지역+오늘 가용시간 |
| 결과 비교 | 반복되는 장소/상품 정보 | 사진+미션명+소요시간+도착 여유 |
| 일정 작성 | 장소 선택·지도 동선·수정 | 2~4개 장소 타임라인과 제거/대체 |
| 반복 접근 | 저장·내 여행·일정 관리 | 하단 내 일정에 저장한 계획 노출 |
| 동행 | 초대·계획 공유 | 가족 제안과 소유자 수락 분리 |
| 여행 중 | 길찾기·현지 정보 | 지도·날씨·예약 조건을 해당 장소에 연결 |

위 표 오른쪽은 제품 제안이며 경쟁사 실제 전환율·성공률을 근거로 한 주장은 아니다.

## 4. 현재 구조의 문제

검토 시점 `web/components/passport-app.tsx`의 홈과 planner 구성을 읽었다. 이 항목은 코드 구조에 대한 관찰이며 렌더된 화면의 시각 QA 결과가 아니다.

1. **홈이 여행을 고르기 전 서비스 기능을 소개한다.** 캠페인 문구·큰 시작 CTA·기능 카드·챕터 목록을 지나 planner에 들어가야 조건과 추천을 본다. 사용자가 알고 싶은 지역·시간과 첫 결과가 분리된다.
2. **여정 결과보다 긴 조건 입력이 먼저 나온다.** planner에는 상황·권역·동행·이동수단·남은 시간·목표시각·공개 거점·경험·도보·추가 버퍼·날씨가 한 묶음이다. 휴대전화에서는 추천 결과에 도달하기 전에 설정 작업을 길게 해야 할 가능성이 있다.
3. **내부 상태가 여행 결과보다 앞선다.** API 연결·수신 건수·출처 상태가 미션 작업영역 상단을 차지한다. 출처는 중요하지만 먼저 보여야 할 것은 어떤 장소들을 오늘 함께 다녀올 수 있는가다.
4. **고유 기능명이 사용 순서를 대신한다.** 복귀 미션, 부모 브리핑룸, 패스포트, 레이더, 데이터 화면을 병렬로 두면 계획→저장→공유→기록의 순서를 사용자가 추론해야 한다.
5. **정보가 모두 같은 무게를 가진다.** 방문 불가·예약 확인은 여행 결정을 바꾸지만, 보정계수와 API 호출 상태는 근거 확인용이다. 한 화면에 같은 크기의 패널로 두면 중요한 조건을 찾기 어려워진다.

부모 사용자를 앞에 두는 것은 홈의 부모 버튼 크기를 키우는 것만으로 해결되지 않는다. 부모도 지역·날짜·도보 조건으로 직접 여행안을 만들고, 저장된 가족 일정에서 제안이 실제 반영되는 구조가 필요하다.

## 5. 권장 모바일 화면 계층

### 하단 내비게이션

**여행 찾기 / 지도 / 내 일정 / 가족**의 네 작업 탭을 제안한다.

- 여행 찾기: 지역·시간 입력과 추천 미션.
- 지도: 현재 지역 및 선택 미션. 선택 결과와 지도 상태가 이어진다.
- 내 일정: 예정된 여행, 저장한 후보, 여행 기록. 기록 안에서 비무장 패스포트 5장을 연다.
- 가족: 받은 초대, 함께 계획하는 일정, 식사·도보 선호, 미션 제안.

패스포트를 감추자는 뜻이 아니다. 내 일정 화면의 상단에 “예정된 여행 / 비무장 패스포트”를 명시해 계획과 완료 기록을 구분한다. 레이더는 관련 호국 장소 상세 또는 내 일정의 “방문 인증 준비”로 연결하고 별도 화면 접근도 유지한다. 데이터·개인정보 원칙은 설정/출처 화면과 장소의 출처 링크로 접근한다.

부모가 처음 들어와도 여행 찾기로 바로 계획할 수 있다. 자녀 초대코드가 없다는 이유로 부모의 독립 탐색을 막지 않는다. 초대 입력은 가족 탭과 상단 보조 진입에서 제공한다.

### 첫 화면

상단은 작은 브랜드명과 가족 초대 진입만 둔다. 질문은 **“오늘, 강원 어디에서 만날까요?”**처럼 시작 행동에 붙인다. 강원 5군과 춘천·속초 관문 중 지역 선택, 2·4·8시간 또는 1박2일 시간을 같은 첫 화면에서 고르게 한다. 첫 주요 CTA는 **“4시간 미션 보기”**처럼 선택 결과를 반영한다.

역할·상황·경험 태그를 모든 탐색의 필수 관문으로 만들지 않는다. 초기 기본 가정은 결과 상단의 요약에 보여주고 수정하게 한다. 자차나 공개 거점을 자동 선택했다면 숨기지 않는다. “철원 · 4시간 · 자차 가정 · 거점 확인 필요”가 결과에 남아야 한다. 사용자가 아직 정하지 않은 값을 안전 확인 완료로 표시하지 않는다.

긴 온보딩 대신 사진이 있는 첫 추천을 빠르게 보여주고, 확정 전에 공개 거점·목표시각·이동수단을 확인한다. 실제 시간 여유가 계산 불가능하면 그 구간은 “조건을 정하면 계산”으로 두어 임의 숫자를 만들지 않는다.

### 추천 결과

첫 화면에 2~3개 미션을 비교하게 한다. 각 카드에는 대표 장소 사진, 미션명, 2~4개 장소 요약, 예상 소요시간, 도착 여유, 가장 중요한 방문 조건을 둔다. 사진은 해당 장소의 검증된 이미지이거나 지역 이미지임을 명시한다. 경쟁사의 사진·UI 자산을 복제하지 않는다.

기본 추천·걷기 적은 후보·비 대비 후보가 실제 데이터와 조건으로 다를 때만 구분한다. 같은 장소를 제목만 바꾼 카드는 피한다. 카드의 대표 행동은 “일정 보기”, 작은 저장 버튼은 후보 저장이다. 선택하지 않은 상태에서 여러 주요 버튼이 경쟁하지 않게 한다.

### 상세와 지도

미션 상세 상단에는 이름·소요시간·추정 여유를 두고 바로 아래에 장소 타임라인을 보여준다. 지도 보기로 바꿔도 같은 미션과 선택 장소를 유지한다. 이동선은 실제 길찾기가 아닌 경우 “장소 연결 표시” 또는 거리 추정임을 알린다.

하단 고정 버튼은 **“이 일정 저장”** 하나를 주요 행동으로 둔다. 장소별 카드는 방문 조건·전화·외부 지도·대체 장소로 이어진다. 여행을 막는 휴무·통제·예약 불가와 미확인 조건은 접어 숨기지 않는다. 산식·출처 상세·API 상태는 사용자가 펼쳐볼 수 있다.

지도를 전체 서비스 첫 화면으로 강제하지 않는다. 지리를 모르는 부모에게는 카드와 장소 이름이 탐색의 출발점이 될 수 있다. 지도 탭을 직접 연 사용자는 공개 장소 탐색을 할 수 있게 하고, 여행 찾기에서 미션을 선택한 사용자는 해당 경로를 먼저 보여준다.

### 저장과 가족 일정

저장 완료 후 내 일정에 같은 장소·순서가 보여야 한다. 저장 동작으로 방문 스탬프를 자동 획득하지 않는다. 여행 후 기록이 패스포트로 이어진다.

가족에게 보낼 때는 실제 공유 가능한 범위를 간단히 검토한다. 부모에게는 여행일·권역·만남 거점·장소 순서·도보·식사 후보가 중심이며 복귀 기준시각과 상세 이동경로는 제외한다. 부모가 “산책 대신 실내 장소 제안”을 보내면 자녀가 수락해야 원본 일정이 바뀐다. 이 행동이 부모 공동 사용자 설계의 핵심이다.

## 7. 재설계 완료를 판단할 행동

- 처음 방문한 사용자가 첫 화면에서 지역과 시간을 선택하고 추천 미션을 볼 수 있다.
- 지도와 목록을 오가도 선택한 미션·장소가 유지된다.
- 시간·부모 도보·날씨 조건을 바꾸면 실제 후보 또는 판정이 바뀐다.
- 저장한 일정이 내 일정에 나타나고 방문 기록과 구분된다.
- 부모가 초대 없이도 여행을 탐색하고, 초대 후에는 허용된 일정에 제안을 남긴다.
- 복귀시각·좌표·민감정보를 공유하지 않으면서 계획 협업이 가능하다.
- 불확실한 방문 조건이 사진이나 밝은 디자인 때문에 감춰지지 않는다.
- 데이터 출처는 심사위원이 쉽게 찾을 수 있고 일반 여행의 주요 행동을 밀어내지 않는다.
