## 제출 형식과 항목

제출매뉴얼 4·6~9쪽 기준:

- 마감은 **2026-09-21 16:00**. 기간 내 수정 가능, 종료 후 수정 불가. 참가 계정 로그인과 등록 이메일 인증이 필요하다.
- 팀명·대표는 수정 불가. 나머지 팀원과 서비스명·개요·유형·지역특화 정보는 최종 개발 결과로 정리한다. 팀원은 콘텐츠랩 가입자만 입력 가능하다.
- 웹은 **서비스 URL**. 앱은 **스토어 등록·승인 완료 링크 최소 1개**. SW/기타는 URL 또는 관련자료 ZIP 1개(50MB 이하). 앱 등록 연장기간은 없다.
- 로그인 필요 시 지정 테스트 계정 제공: 일반 ID `openapi`, PW `2026openapi!` 또는 안내된 이메일 ID 형식. 이는 안내서의 공용 심사용 계정 규격이며 실제 사용자 비밀번호가 아니다. 로그인 불필요·SNS 연동은 별도 계정 불필요.
- 실제 활용 공사 OpenAPI 최소 1개 이상 선택. 활용한 신청자들의 인코딩·디코딩 키 모두 입력. 화면에는 키 쌍 최소 1개·최대 3개로 안내되어 있다.
- 기능설명서는 지정 양식으로 작성한 **PDF 1개, 10MB 이하**. 임의 양식 사용이나 항목 누락·변경은 제외 사유가 될 수 있다.

## 기능설명서 내용·분량

양식 1~9쪽 기준:

1. 팀명·서비스명.
2. 서비스명·유형·한 문장 개요·주제 선정 이유.
3. 핵심 기능 목록.
4. 대표 이미지 1개, 주요 화면 이미지 3~5개.
5. 지역특화 구현: 강원특별자치도 및 접경 시군 연계 내용. 같은 광역자치단체 내 복수 기초지자체 허용. 이 서비스는 해당하므로 반드시 작성한다.
6. 핵심 기능별 흐름도: **핵심 기능 최대 5개**, 필요 시 해당 슬라이드를 복사하여 작성. 화면 캡처와 동작 설명을 함께 넣는다.
7. 실제 활용한 공사 OpenAPI 목록과 활용방식.
8. 기타 API·파일데이터 및 활용방식(해당 없으면 삭제 가능).
9. 차별성·발전계획.

확인한 양식에는 별도 총 페이지 상한이나 최소 글자 크기가 적혀 있지 않다. 기본 양식은 9쪽이며 핵심 기능 페이지의 복사가 명시적으로 허용된다. 예비 제안서의 5쪽·12pt 규칙을 1차 기능설명서에 적용하지 않는다. 작성 시 안내 문구·가이드 박스는 양식의 지시에 따라 제거하고 항목 구조를 유지한다.

## 키 제출과 운영계정

키 가이드 3~5·10쪽 기준:

- 인코딩키와 디코딩키를 모두 제출한다. 인증키 발급현황 메뉴에서 한 종류만 복사하는 실수를 피해야 한다.
- 주최 측은 **개발기간의 API별 호출 수와 서비스 내부 활용내용**을 함께 확인한다. 단순 호출 테스트만 한 API는 활용 API로 제출하지 않는다.
- 실제 사용 API의 신청자가 다르면 각 신청자의 키를 제출한다. 키는 앱 번들·공개 Git·보고서에 넣지 않고 서버 환경변수와 제출 시스템에서만 취급한다.
- 운영계정 전환은 최신 가이드에서 **선택**이다. 신청한다면 실제 활용 API 중 대표 1개에 대해 팀당 1번, 서비스 개발과 확인 가능한 URL 준비 후, 1차 제출 기한 안에 신청한다.
- 전환 신청서에 공모전 서비스명·URL 및 `[공모전 웹·앱 개발 부문 제출 서비스]` 문구를 넣는다. 승인·반려 자체는 공모전 심사와 무관하다.
- 초기 OT 18쪽의 운영계정 신청 예고를 필수로 확대 해석하지 않는다. 구체적인 최신 키 가이드의 선택 표기가 우선이다.

## 영상·서버 운영·추가 제한

- **시연영상 의무 제출, 길이, 해상도, 파일규격은 위 네 자료에서 확인되지 않았다.** 공식 필수 항목으로 단정하지 않는다. 개발팀의 영상 제작은 시연 대비 권고이며, 최신 참가자 Notion의 추가 공지가 있을 때 반영한다.
- **서버를 특정 날짜까지 유지해야 한다는 종료일 또는 최소 운영개월 수는 위 네 자료에 명시되어 있지 않다.** 기능심사는 실제 서비스에 접근하여 진행하므로 제출 URL과 테스트 접근을 심사기간 중 유지하는 것은 실행 계획에 포함한다. 대회 후 영구운영을 규정으로 단정하지 않는다.
- **Vercel·Railway 등 특정 배포사, 자체 도메인 구매 의무, 유료 서버 의무는 확인되지 않았다.** OT 21쪽은 서버·도메인 비용 지원이 없고 프리티어 활용을 권장한다.
- OT 19~20쪽은 웹·앱 형태가 평가에 영향을 주지 않으며, 생성형 AI 및 AI 코딩도구 사용에도 감점·제한이 없다고 안내한다. 따라서 1차는 **웹/PWA URL 제출**이 합리적이다.
- OT 10·16·18쪽은 공사 파일데이터만 사용해서는 OpenAPI 필수 요건을 충족할 수 없다고 안내한다. JSON 캐시와 장애 대체 데이터는 실제 API 활용을 보조해야 한다.
- OT 22쪽은 공사 명칭·로고 사용을 제한한다. 이후 참가자 Notion FAQ를 주 작업에서 확인한 결과, **텍스트 출처 표기는 금지 대상이 아니며 필요**하고 CI/BI 이미지의 무단사용을 피해야 한다. 표기 예: `출처: ⓒ한국관광공사` 또는 `출처: ⓒ한국관광콘텐츠랩`; `TourAPI`만으로 출처를 표시하지 않는다. [참가자 최신 안내](https://lowly-polyanthus-1fb.notion.site/2026-36b5dce406e380e0a3d1f80525667a11).
- 최종 PT 자료는 별도 안내 대상이다(OT 13쪽). 1차 기능설명서를 최종 발표자료 규격으로 간주하지 않는다.
