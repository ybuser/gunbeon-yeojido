# 1차 심사용 구현 계획 — 2026-09-07 갱신

팀: 우리아들이군인인데여행계획을준비했대
서비스: 군번여지도 강원: 휴전선 밖 첫 하루
기준: ① 웹·앱 개발 부문. 기능설명서 9/21 16시 마감. 규정은 official_rules.md, notion_requirements.md, submission_assets.md에 분리.

## 제품 정의

장병과 부모가 제한된 하루 안에 실행할 수 있는 강원 여행을 함께 결정하는 관광 여권. 장소 개수가 아니라 시간·방문 조건·가족 도보 부담에 따라 실제 미션이 바뀌는 경험이 차별성이다. 최초 공개 거점은 관광자료에 등재된 공개 관광장소만 제공한다. 정확한 군 복귀 경로는 입력/저장/공유하지 않는다.

## 디자인

컨셉: 실제 여행 사진과 조건 비교를 중심으로 한 가족 여행 플래너. 흰 바탕, 차콜 글자, 청색 동작 버튼을 사용한다. 총기·위장·계급·부대마크·군복 인물 없음. 장식 이모티콘 없이 기능을 나타내는 단순 선형 아이콘 사용. 모바일 하단4메뉴, 최소46px 동작 버튼, 칩/날짜 입력, 읽기 쉬운 대비, 데스크톱 2열 작업면. 사진은 해당 장소의 TourAPI 제공 사진을 사용하며 출처를 표시한다. 큰 마케팅 블록을 여러 페이지에 반복하지 않는다.

화면: 홈(역할과 첫 행동) / 복귀 미션(조건→지도→시간 산식→방문 조건→여권) / 부모 브리핑(초대와 독립 조건→가족 제안) / 여권(5장·스탬프·권한·비식별 카드) / 레이더(후보와 준비 체크) / 데이터 출처(실호출 상태·정규화 근거).

## 우선순위

- P0: 반응형/PWA, 역할/상황/7권역/시간/수단/공개거점, place_node, 실제 국문 API 호출 어댑터, 복귀시계/2~4장소 미션, 방문 조건 디코더, 부모 독립 브리핑, 최소 초대/공유권한(local demo), 패스포트·비식별 공유, 출처/오류 대응/검증 보고서.
- P1: 무장애 정보 심화, 휴가회수 레이더 준비 UX, 기상청 실제 연동, 가족 식사 선호, 별도 기기 간 초대 연결. 레이더·선호 UI는 첫 버전에 선구현 가능하지만 실보상/실식단을 주장하지 않는다.
- P2: 집중률 전체 매칭, 중심·연관 관광지 추천 가중치, TAGO 환승·막차, 공개 식단·혜택.

## 기술 선택

React19+TypeScript+Tailwind4, Next.js App Router 호환 Vinext/Sites 런타임, 서버 API routes, 로컬 데모 여권은 localStorage, 핵심 계산은 순수 함수. Kakao JS 지도키가 없을 때 지리 개략도 명시. 공식 TourAPI는 no-store 실시간 HTTP 호출; 통일부/보훈부 정규화는 별도 공개 원천. 공통키를 이용한 공공 API 6종 표본 인증 및 호출을 확인했다. 앱에서는 국문·무장애·기상청을 사용하며, 추가 3종은 추천에 통합되지 않았다. Sites는 현재 private 개발 배포이며 심사용 외부 접근이 가능한 URL은 별도 확인 필요. 소스 기준 GitHub ybuser/gunbeon-yeojido.

## 마일스톤

현재 코드 점검과 다환경 브라우저 QA 결과는 [검증 보고서](browser_qa_report.md), 이후 일정과 완료 기준은 [점검 이후 개발 계획](next_steps_after_review.md)을 기준으로 한다. 저장·가족 제안의 장소 참조 보존, 준비/방문 기록 구분, 방문 조건·예보 유효범위, 브라우저 뒤로가기와 작은 화면 표시를 보완했다.

다음 범위는 대표 미션 2개 깊이 검증, 5군 기본 탐색 점검, 실제 부모·장병 사용 확인, 심사 접근과 지정 제출물 준비다. 실제 별도 기기 가족 연결은 구현 완료로 간주하지 않고 별도 범위 결정이 필요하다.
