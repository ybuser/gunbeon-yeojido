## 제품 방향

장병과 부모가 **같은 강원 여행안을 보고, 선택한 만남 장소까지 돌아갈 여유와 방문 조건을 확인하는 경험**에 집중한다. 기능을 더 늘리기보다 장소·순서·조건·기록이 서로 일치하는지 확인한다. 기본 여행안은 간결하게 제공하고, 데이터 없는 평화·호국·무장애·보상 적합성을 붙이지 않는다.

## 9/8 완료 반영

외부 비밀번호 체험, 코스 사진 표지, 새 코스/추천 가져오기/장소·순서·시간 편집을 구현했다. TourAPI 검색과 저장 ID 재조회, 직접 장소와 지도 선택을 연결했고 Chrome·Edge 네 화면 크기의 직접 코스 흐름을 통과했다. [직접 코스 구현 기록](custom_trip_delivery.md). 임시 로그인은 정식 회원 계정과 다르며 현재 여권은 브라우저 저장이다.

추가로 개인 장소 즐겨찾기·지도 만남 선택, 빈 코스 저장, 여행 완료 확인과 스탬프 선택을 구현했다. 계획의 시간은 출발 예정 기준으로 고정하고, 현재 출타는 시작 확인 후 실제 시간과 장소 진행을 반영한다. 즐겨찾기 변경이 저장 여행을 바꾸지 않으며 출타 상태를 새로고침 후 복원한다. [최신 구현·공개 QA](planning_outing_delivery.md).

## 이번 수정·QA 범위

이번 범위는 저장·제안의 장소 보존, 운영 조건과 예보 범위 반영, 준비/방문 기록 구분, 브라우저·화면 크기별 흐름 점검이다. 가족 연결은 같은 브라우저에서 역할을 전환하는 체험 범위로 검증한다. 여러 브라우저나 실기기에서 각각 주요 기능을 확인하는 것과 기기 사이에 같은 여행안·초대 권한이 동기화되는 것은 별개다. 별도 기기 동기화, 자동 환승 최적화, 새 보상·식단 API 구현은 이번 수정·QA에 포함하지 않는다.

저장→새로고침→다시 보기와 부모 제안→같은 장소 검토→저장의 일관성을 먼저 확인한다. [브라우저 QA 보고서](browser_qa_report.md)에 수정 확인·잔여 결함·미검증 환경을 구분하고, 이미 수정·확인한 항목은 다음 개발에서 반복하지 않는다. 아래 실사용 확인과 별도 기기 연결 판단은 이번 QA 이후 단계다.

## 유지할 개발 증빙

- 재현 가능한 결함은 GitHub 이슈, 해결 범위는 PR, 변경 이유는 작은 커밋으로 남긴다.
- 단위 검사와 키 없는 브라우저 장애 흐름은 CI에서 반복한다. 실제 API·Chrome·Edge 검증은 환경·버전·시각·호출 수를 별도 기록한다.
- 스크린샷은 실행한 상태만 남긴다. 테스트 통과, 현장 운영 검증, 실제 사용자 사용성을 서로 바꾸어 표현하지 않는다. 실행 환경·코드 버전·남은 미검증 항목은 [브라우저 QA 보고서](browser_qa_report.md)와 연결한다.
- API 원문·키·개인 계정·정확한 복귀시각을 증빙에 포함하지 않는다.
