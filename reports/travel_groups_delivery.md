# 그룹 여행 및 호출 효율 개선

2026-09-08 · 2026 관광데이터 활용 공모전 **① 웹·앱 개발 부문**

## 제품 결정

서비스의 시작점을 관광지 목록에서 **예정된 개인 여행과 소속 그룹**으로 바꿨다. 가족·연인·친구·동행 그룹을 여러 개 만들고, 각 그룹에서 여러 여행을 관리한다. 강원 5군과 춘천·속초 관문이라는 범위는 유지한다. 부모 브리핑은 동행 준비 도구로 남기되, 참여·공유는 모든 유형이 쓰는 그룹으로 통일했다.

- 홈 → 그룹 → 일정 보기·수정 / 새 그룹 여행 / 내 여행에서 가져오기
- 둘러보기는 출발 예정 **연·월·일·요일·시각**을 표시하고 한 번 눌러 바꾼다. 브라우저 뒤로 가기·새로고침도 해당 탭을 복원한다.
- 그룹 일정에는 출발 예정 시각·장소 참조·체류/도보 시간·순서를 저장한다. 복귀시각은 개인별로 정한다.
- 직접 지정한 만남 장소·주소·좌표는 공유 확인창에서 포함을 선택한 경우에만 그룹에 저장한다. 공개 기록 카드에서는 계속 제외한다.
- 빈 일정도 저장할 수 있다. 현재 출타·여행 완료 확인·개인 스탬프는 기존 기능을 유지한다.
- 같은 브라우저에서만 동작하던 8자리 가족 체험 초대 UI를 서버 그룹 초대로 교체했다.

## 기술 결정

기존 React/TypeScript/Vinext/Sites를 유지하고 D1을 그룹 저장소로 추가했다. Drizzle 스키마와 버전별 SQL 마이그레이션을 저장하며 런타임 테이블 생성은 하지 않는다. 관광공사 응답 본문을 저장하는 테이블은 없다.

브라우저 참여 토큰은 180일 HttpOnly 쿠키, 서버에는 토큰 해시를 보관한다. 초대는 72시간 유효하고 원문 토큰을 DB에 저장하지 않는다. 생성자가 초대·회수·멤버 제외·그룹 삭제를 관리한다. 일반 멤버는 일정을 함께 편집할 수 있으며 삭제는 작성자 또는 관리자만 가능하다. 탈퇴·제외 이전에 발급된 초대로는 재참여할 수 없다. 이는 본인인증 계정이 아닌 테스트용 참여 방식이며, 쿠키가 사라지면 새 초대가 필요하고 기존 관리자 권한 복구는 아직 없다.

동시 수정은 버전 번호로 검사해 409를 반환한다. 뒤늦게 저장하는 사용자는 내용을 덮어쓰지 않고 새 여행 사본으로 보관할 수 있다. 그룹 전환 후 늦은 응답이 다른 그룹 화면·초대를 덮지 않도록 요청 대상과 순서를 확인한다.

## 데이터 운영

`ALL_CATEGORIES_FAILED`의 실제 하위 원인은 TourAPI `areaBasedList2`의 HTTP 429 / reason 22(일일 한도 초과)였다. 코드 조회는 성공했다. 일일 오류와 순간 호출 제한을 구분하고, 첫 카테고리가 한도 초과면 나머지 네 요청을 생략한다. 서버에는 오류 코드·재시도 시각만 기록해 10분 동안 같은 오퍼레이션 반복 요청을 막는다. 10분 뒤 제공자가 복구된다는 뜻은 아니다.

앱 API 응답은 페이지 메모리에서 공유한다. 메뉴 이동 시 같은 요청을 다시 보내지 않으며 새로고침 시 초기화된다. 명시적인 다시 확인은 캐시를 비우고 요청한다. 서버 그룹 데이터는 공동 편집 때문에 저장 직후·화면 재진입·변경사항 확인 때 최신 내용을 읽는다.

이미지는 CORS가 허용되는 경우 브라우저 Blob 메모리로 보관한다(최대 48 MiB). 허용하지 않는 출처는 원본 이미지 로딩과 브라우저 캐시를 사용한다. 이미지 제공자가 브라우저 캐시까지 금지하면 재사용을 보장하지 않는다. Service Worker에는 관광 API 응답을 저장하지 않는다. 별도 브라우저 탭 사이 공유는 하지 않는다.

[공식 저장 정책·운영 결정·신청 초안](tourapi_operations_policy.md)을 참고한다. 담당자에게 이메일은 발송하지 않았다.

## 로고와 화면

종이비행기를 여권의 모서리, 강원 능선, 여정의 점을 결합한 SVG 심벌로 교체했다. 웹 헤더·입장 화면·파비콘·PWA 아이콘에 같은 형태를 적용했다. 흰 배경과 짙은 글자, 제한적인 파란 강조를 유지하고 그룹은 첫 글자로 구분한다. 이모지·군사 장비 이미지는 사용하지 않는다.

## 검증

- 단위 검사 55개: 기존 여행/복귀 계산, 공유 화이트리스트, 잘못된 값, 메모리 요청 중복·취소·재시도, 한도 오류 파싱·팬아웃 중단.
- 그룹 API: 격리 세션 3개, 11개 케이스·94요청 통과. 권한·초대 회수·탈퇴·동시 수정·삭제·빈 일정 검증. 생성한 테스트 그룹은 삭제하며 테스트 프로필은 삭제 API가 없어 남는다.
- 그룹 UI: 실제 Chrome·Edge, 360×740 / 430×932 / 1440×900 / 1920×1080 뷰포트. 날짜 편집, 그룹 2개 생성, 빈 일정 저장·수정, 홈 이동, 가로 넘침 검증.
- 추가 360px/1440px Chrome·Edge 검사: 초대 링크 → 테스트 로그인 → 다른 세션 참여 → 동일 일정 표시.
- TourAPI 목록은 한도 초과 상태를 명시한 테스트 응답으로 격리했다. 실제 목록 호출 성공을 이번 UI 검사로 주장하지 않는다. 지도·무장애·기상청은 해당 요청별 상태를 구분한다.
- 실제 휴대폰 기기·모바일 운영체제 Safari 검증은 포함하지 않는다. 전체 lint에는 기존 엄격 규칙 및 React effect 패턴 관련 실패가 남아 있어 통과로 표기하지 않는다.

검증 스크립트: `web/scripts/groups-ui-qa.mjs`, `groups-api-qa.mjs`, `browser-qa.mjs`, `custom-trip-qa.mjs`, `planning-outing-qa.mjs`.
