# 군번여지도 ‘한 수 보태기’ — 외부 조언과 재공유 기획

2026-09-09 · 공식 자료 조사 기반 제안 · 사이트 구현/외부 게시 미수행

## 권고

**‘이 코스, 한 곳만 바꾼다면?’**이라는 질문으로 여행 계획을 공유하고, 외부인이 관광지에 구체적인 제안을 붙이는 **‘한 수 보태기’**를 만든다. 작성자가 제안을 실제 계획에 반영하면 바뀐 하루를 보여주고, 참여자는 그 계획을 자기 여행의 출발점으로 가져간다.

핵심 재미는 점수나 댓글 수가 아니라 **‘내가 알려준 곳이 그 사람의 여행에 들어갔다’**, **‘같은 강원 지역을 나는 이렇게 돌겠다’**는 영향력과 취향 표현이다. 기존 ‘하루 여권’ 표지와 연결하면 별도 SNS를 만들지 않고도 군번여지도만의 공유 경험이 된다. 바이럴 효과는 아직 검증되지 않은 제품 가설이다.

## 유입→참여→반영→재공유

| 단계 | 사용자가 보는 것 / 행동 | 다음 단계의 이유 |
|---|---|---|
| 작성 | 내 여행의 ‘한 수 부탁하기’ → 질문 하나 선택 → 공개 미리보기 → 링크 발행 | 막연한 ‘의견 주세요’ 대신 답하기 쉬운 질문 |
| 유입 | 인스타 스토리/게시물 또는 X에서 지역·관광지·질문이 있는 카드 | ‘고성 코스, 한 곳 바꾼다면?’처럼 내가 답할 틈이 보임 |
| 참여 | 앱 설치 없이 공개 계획 확인 → 장소 선택 → ‘대신 이곳/한 곳 보태기/여유 있게’ 제안 | 설명을 길게 쓰지 않아도 계획에 구체적으로 기여 |
| 반영 | 작성자가 원본과 제안 비교 → 개인 편집기로 가져오기 → 저장 | 제안이 실제 여행을 바꾸며 기존 여유 조정·TourAPI가 활용됨 |
| 인정 | 해당 제안에 ‘작성자가 일정에 반영했어요’ 표시, 이전/이후 장소 차이 | 참여자가 자기 기여를 확인. 외부 자동 알림·DM은 없음 |
| 재공유 | 작성자 ‘이렇게 바뀌었어요’ 카드 / 참여자 ‘이 코스로 내 여행 만들기’ | 결과가 새 콘텐츠가 되고 다음 작성자로 이어짐 |

반영 전 ‘반영 완료’라 표시하지 않는다. 공개 제안을 채택하는 것, 개인 일정에 적용한 것, 여행을 완료한 것은 서로 다른 상태다. 새 공유나 SNS 게시도 자동 수행하지 않는다.

## 첫 구현 범위

### A. 작성자는 질문 하나만 고른다

권장 질문 프리셋:

- ‘이 코스, 한 곳만 바꾼다면?’
- ‘중간에 밥 한 끼, 어디가 좋을까요?’
- ‘조금 덜 걷고 싶어요. 어디를 바꿀까요?’

계획 title·그룹명·개인 메모를 그대로 가져오기보다 공개 표준 제목을 기본 제공한다. 예: **‘고성 하루, 한 수 부탁해요’**. 사용자에게 공개된 장소 목록을 확인시키고 제외할 장소를 고르게 한다. 공공 관광지 0개인 계획은 개인 계획 저장은 그대로 가능하지만 공개 조언 카드에는 먼저 공유할 공공 관광지를 추가하도록 안내한다.

공개 내용은 권역, 공공 관광지 이름/순서, 질문 종류, 선택한 관광 목적 정도다. 출발 날짜·시각·복귀 기준·군번·부대·개인 만남 장소·정확한 좌표·그룹 멤버/실명·전체 경로를 공개하지 않는다. 관광지 연결은 지도 타일 없는 순서 개념도다.

### B. 참여자는 계획을 망가뜨리지 않고 제안한다

첫 화면의 주 행동은 ‘한 수 보태기’. 일반 댓글 입력창을 가장 먼저 보여주지 않는다.

1. **대신 이곳:** 기존 관광지 하나를 선택하고 대체 관광지/음식점을 TourAPI 검색에서 고른다.
2. **한 곳 보태기:** 장소를 고르고 기존 코스의 어느 장소 다음인지 선택한다.
3. **조금 여유 있게:** 기존 관광지에 ‘이번에는 빼도 괜찮아요’ 또는 ‘짧게 둘러봐도 좋아요’ 의견을 남긴다. 검증되지 않은 시간 절감이나 안전 보장은 표시하지 않는다.

이유는 ‘식사로 좋아요 / 덜 걸어요 / 실내에서 쉬어요 / 제가 가봤어요’ 같은 선택형 문구와 선택적 짧은 설명으로 구성한다. **참여자의 의견**이라는 표시는 유지하며, ‘실내’·‘덜 걷기’ 의견을 공공데이터의 확인된 사실로 승격하지 않는다. 비슷한 제안은 합쳐 보여주되 추천 인기 순위/명예 배지/군 계급을 만들지 않는다.

첫 범위의 대상 장소 검색은 현재 서비스의 정상 TourAPI 검색을 사용한다. 주요 기능을 몇 개 샘플/수동 목록으로 대체하지 않는다. 가입 없는 조회/참여는 게스트 세션으로 가능하게 하고, 별명은 선택 사항으로 둔다. SNS 계정 연결이나 부대 인증은 요구하지 않는다. 다만 게스트 별명은 검증된 실명으로 표시하지 않는다.

### C. 반영은 작성자만 한다

참여자가 공개 링크를 알아도 원본·그룹 계획을 직접 수정할 수 없다. 작성자가 제안을 열면 원래안/제안안의 장소 변화를 확인한다. 개인 출발·복귀 계산은 로그인/개인 편집기에서만 기존 여유 조정 계산으로 평가한다.

‘내 계획에서 검토’로 편집기를 열고 저장한 다음에만 반영 상태를 기록한다. 원본이 이미 달라져 대상 stop이 없어졌다면 ‘계획이 바뀌었어요. 다시 확인’으로 처리한다. 중간 취소/오류/활성 출타 편집 잠금에서는 제안을 반영 완료로 바꾸지 않는다. 기존 완료 기록이나 진행 중 출타 사본을 조언으로 덮어쓰지 않는다.

공개 페이지에는 선택적으로 변경된 **공공 관광지 목록만** 업데이트한다. 원래 비공개 계획의 자동 동기화 피드로 만들지 않는다. 반영 취소/다른 안 선택도 사실대로 표시할 수 있어야 한다.

### D. 참여자의 다음 여행

제안 제출 후 ‘고마워요’만 띄우지 말고 **‘이 코스로 내 여행 만들기’**를 제공한다. 공개 장소만 가져온 새 개인 코스를 만들고 출발 날짜·만남 장소·복귀 기준은 새 사용자가 직접 정한다. 원 작성자의 개인 시간·초대권한·완료 스탬프·기록은 복사하지 않는다.

원하는 사람이 자기 취향으로 바꿔 다시 ‘한 수 부탁하기’를 발행할 수 있게 한다. 공개 페이지 출처는 작은 ‘이 여행안에서 시작했어요’ 링크로 남길 수 있지만, 원 작성자의 실명/계정 연결을 강제하지 않는다. 첫 구현에서는 공개 피드·전체 검색·팔로우·랭킹·리워드는 불필요하다.

## 실제 인스타/X 공유 방법

### X

공식 Web Intent로 질문과 공개 URL이 미리 채워진 작성 창을 연다. **마지막 게시 버튼은 사용자가 누른다.** 창이 열렸다는 사실을 ‘게시 완료’로 기록하지 않는다. 별도 X 로그인 토큰을 서비스가 보관하거나 게시 API를 구매할 필요가 없는 경로다. [X 공식 Web Intents](https://docs.x.com/x-for-websites/web-intents/overview)

예시 문구: ‘고성 하루 코스 짜봤어요. 한 곳만 바꾼다면 어디로 갈까요? 군번여지도에서 한 수 보태주세요. [공개 링크]’

### Instagram

첫 버전은 **세로 PNG 저장 + 공개 링크 복사 + 스토리에 링크 스티커 붙이기**가 확실한 기본 흐름이다. Instagram 자동 게시/스토리 딥링크가 모든 모바일 웹에서 된다고 약속하지 않는다. 모바일 공유 시트는 지원 여부에 따라 보조 수단으로 제공한다.

Meta는 카메라롤에서 사진/영상을 고른 뒤 링크 스티커에 URL을 넣는 방식을 공식 안내한다. 신규·제한 계정 등 예외가 있고, 이 공식 안내는 2021년 자료이므로 출시 전 실제 iOS/Android의 현행 UI를 확인한다. [Meta 링크 스티커 공식 안내](https://about.fb.com/ja/news/2021/10/linkaccessstickers/)

카드는 SVG만 내려주지 않고 인스타가 바로 선택할 수 있는 PNG로 제공한다. 첫 범위는 자체 벡터+관광지 이름 기반, 스토리 1080×1920과 일반 공유용 카드 중 최소 1종을 완성한다. 웹페이지 사진이 보이는 것과 SNS 재배포 허용은 다르므로 사진은 이용조건·CORS 내보내기 검증한 자산만 적용한다. 링크는 스토리 이미지 위에 사용자 스티커를 놓을 공간을 둔다. QR은 보조 수단이며 같은 휴대폰에서 QR만 제공하지 않는다.

‘한 수 요청’ 카드: 질문이 제목, 장소 2–4개, ‘너라면 어디를 바꿀래?’ CTA. ‘반영 결과’ 카드: 실제 채택한 장소의 전/후 한 쌍과 ‘한 수 덕분에 이렇게 바뀌었어요’. 참여자의 별명은 공개 동의가 있는 경우만 선택적으로 표시하고 기본은 ‘한 수 덕분에’다.

## 공개 링크와 운영 설계에서 빠지면 안 되는 것

- 현재 서비스의 비밀번호 1234 입구가 공개 조언 페이지까지 막으면 SNS 방문자는 참여 목적을 이해하기 전에 이탈한다. `/p/:slug`처럼 **명시적으로 공개한 안전한 투영만** 로그인 없이 제공한다. 기존 개인 여행/그룹/관리 API는 종전 인증을 유지한다.
- 공개 URL은 그룹 초대코드·원본 recordId·owner token과 분리한다. 공개 읽기/제안 쓰기/작성자 관리 권한을 구별한다. 작성자는 제안 닫기·페이지 철회·부적절한 제안 숨기기를 할 수 있어야 한다.
- 공개 기록에는 사용자가 발행한 장소 참조·질문·제안·반영 상태만 저장한다. TourAPI 응답 DB 캐싱 허용을 임의로 가정하지 않는다. 정상 TourAPI 검색·상세는 유지하고 현재 허용된 방식으로 해결한다.
- 자동으로 키보드 입력마다 검색하지 않고 명시적 검색/적절한 중복 요청 방지, 게스트 세션별 요청 제한, 오류 안내를 둔다. 이는 정상 기능 축소가 아니라 공개 입력의 운영 보호다. 호출 한도 해결을 위해 정상 조회를 샘플로 바꾸지 않는다.
- 댓글을 받는 만큼 텍스트 길이 제한·HTML escape·링크/개인정보 입력 안내·신고/숨김·요청 속도 제한은 최소 범위에 포함한다. X/인스타에 제안 답글을 자동 전송하지 않는다.
- 작성자가 페이지를 철회하면 새 열람/제안/가져오기를 막고 안내한다. 외부 SNS에 이미 저장된 카드까지 원격으로 지울 수 있다는 문구는 쓰지 않는다.
- 링크 미리보기는 해시 경로만으로 처리하지 말고 공개 URL의 OG 제목/설명/안전한 이미지가 읽히게 한다. 테스트 비밀번호가 OG 크롤러를 막지 않는지 확인한다. 공개 미리보기 캐시 갱신이 즉시 된다고 약속하지 않는다.

## 1차 시연과 검증

**시연 1:** 작성자 브라우저에서 고성 3곳 계획 → 질문 선택·안전한 공개 미리보기 → 링크 발행. 다른 브라우저/쿠키 없는 창에서 로그인 없이 열람·TourAPI로 음식점 제안. 작성자가 원본 편집에서 반영·저장하고 공개 결과에 변경이 보임.

**시연 2:** 참여자가 ‘이 코스로 내 여행 만들기’ → 공개 관광지만 새 개인 계획으로 복사 → 날짜·복귀·만남 장소 새 입력 → 자기 질문으로 재공유. 원본 plan/그룹/활성 출타/완료 기록이 변하지 않음.

**오류 시연:** 원본 수정 뒤 낡은 제안 적용, 취소, API 실패/재시도, 중복 제출, 링크 철회, 민감한 직접입력 장소 포함 계획, guest가 owner action 위조. 어느 경우에도 허위 ‘반영됨’·공개정보 유출이 없어야 한다.

초기 성공 지표는 공개 링크 열람→실제 제안 제출 비율, 작성자 검토/실제 반영률, 제안자→새 계획 저장률, 변경 카드 재공유 시도다. 공유창 열기/링크 복사는 게시 완료와 구분한다. 숫자를 꾸미지 말고 5–10쌍의 사용성 관찰에서 ‘무엇을 보태면 되는지’ 이해와 도움이 되는 제안이 나오는지 먼저 검증한다.

추천 우선순위는 **공개 안전 투영 + 구체적 제안 + 작성자 실제 반영 + 내 여행 복사 + PNG/링크 공유**다. 여기에 재미를 더하려고 댓글·투표·랭킹·AI 채팅을 모두 추가하면 기능심사에서 핵심이 흐려진다.
