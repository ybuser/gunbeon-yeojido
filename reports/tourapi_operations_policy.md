## 1. 현재 운영 결정

관광공사 응답을 운영 서버 DB에 적재하거나 정기 동기화하여 제공하는 방식은 별도 신청 절차와 허용 범위를 확인한 뒤 적용한다. 현재 서버는 관광공사 장소·상세 응답을 운영 DB에 저장하지 않는다. 호출 효율 개선과 트래픽 증설은 저장 방식 신청과 구분해 진행한다.

이 결정은 일반적인 공공데이터 이용허락만으로 API 운영 정책과 공모전 참가자 안내를 대체하지 않기 위한 것이다. 원문이 요구하는 것은 **별도 신청서 작성과 담당 부서 문의**다. 사전승인을 받아야 하는지, 신청서 제출만으로 시작 가능한지는 명시되지 않았으므로 이 문서에서 임의로 확정하지 않는다.

## 5. 호출 효율 전략

현재 국문 권역 조회는 보통 법정동 코드 2회와 콘텐츠 유형 5회의 **최대 7회 외부 호출**을 만든다. 장소 상세는 국문 2회·무장애 1회, 무장애 권역 조회는 코드 2회·목록 1회·후보 상세 최대 4회를 사용한다. 앱의 `/api/places` 1회와 제공자 요청 1회를 같은 단위로 집계하면 안 된다.

다음은 구현·허용 범위를 확인하며 적용할 운영 계획이다.

1. **중복 작업을 줄인다.** 탭 이동·같은 조건 재적용·빠른 연속 클릭이 같은 외부 호출을 새로 만들지 않게 한다. 진행 중 요청 공유와 완료 응답 재사용은 기술적으로 구분하고, 후자는 저장 정책 문의 범위에 포함한다.
2. **필요한 순간에 조회한다.** 상세·무장애 정보는 실제로 펼친 장소를 중심으로 조회한다. 사용자가 정하지 않은 권역 전체를 미리 수집하거나 매 화면 이동마다 같은 5개 유형을 재조회하지 않는다.
3. **변하지 않은 조건으로 재요청하지 않는다.** 역할·도보·시간만 달라졌다면 이미 표시 중인 후보를 이용한 계산과 데이터 재조회 필요성을 분리한다. 오래 열린 페이지의 정보는 최신 확인 여부를 명시한다.
4. **실패를 종류별로 처리한다.** 22는 일일 한도 안내와 제한된 복구 확인, 23·일반 429는 제공자 안내에 따른 대기와 제한된 재시도, 인증 오류는 신청·키 설정 확인으로 보낸다. 반복 버튼으로 외부 API를 연속 호출하지 않는다.
5. **검증과 시연의 호출량을 통제한다.** 전체 수집 스크립트·반복 브라우저 QA·공개 서비스가 같은 승인 한도를 소비할 수 있음을 반영한다. 이미 성공한 조건을 이유 없이 재검증하지 않는다.
6. **대체 데이터는 출처를 분리한다.** TourAPI 실패 시 다른 이용조건으로 확보한 DMZ·현충시설 자료를 제공할 수 있지만 관광공사 실시간 응답으로 표기하지 않는다. 실패 상태와 확인 시각을 함께 보여준다.

운영 지표는 API별 외부 호출 수, 성공률, 22/23 발생 건수, 사용자 동작당 호출 수, 불필요한 중복 수다. 요청 한도를 회피하기 위한 다계정·키 교체·우회 수집은 전략에 포함하지 않는다.

## 6. 트래픽 증설 단계

국문 카탈로그는 개발계정 신청 가능 트래픽 1,000, 운영계정은 활용사례를 등록하고 신청하면 증가 가능하다고 안내한다. 개발은 자동승인, 운영은 심의승인이다. **현재 우리 계정에 실제 승인된 한도는 미확인**이며 증설량·처리 기간도 확정되지 않았다. [공식 트래픽·심의 안내](https://www.data.go.kr/data/15101578/openapi.do)

1. API 신청자 계정에서 국문·무장애 각각의 활용 승인 상태, 이용 기간, 현재 한도와 실제 사용량을 확인한다. 국문 코드 조회 성공만으로 장소 목록 한도가 남았다고 판단하지 않는다.
2. 예상 일일 외부 호출량을 계산한다. 예를 들어 첫 권역 조회 100회는 중복 제거 전 국문 요청 최대 700회다. 상세·가족 화면·검증 호출과 실제 페이징량을 더해 요구량을 만든다. 이는 계획 예시이며 실제 이용자 수나 쿼터 보장값이 아니다.
3. 완료된 서비스 URL, 실제 API 활용 화면·기능, 서비스 설명과 트래픽 산출 근거를 준비한다. 계정의 활용사례 등록·운영계정 신청 흐름에서 필요한 자료를 제출하도록 준비한다.
4. 공모전 안내에 맞는 신청자 정보와 서비스 식별값을 사용한다. 제출용 키는 지정 제출 경로에서만 취급한다. DB 저장 문의·신청과 트래픽 증설 신청은 서로의 승인을 대체하지 않는다.
5. 승인 결과와 적용 한도를 확인한 뒤 한 번의 제한된 목록 조회로 복구를 점검한다. 확대된 한도를 추정하거나 반복 호출로 탐색하지 않는다.
6. API별 경고 기준과 호출 예산을 설정하고 기능심사 기간의 실제 사용량을 점검한다. 제공자가 안내하지 않은 초기화 시각은 앱 안내에 넣지 않는다.
