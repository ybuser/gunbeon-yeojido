## API 및 증빙 경계

실제 키로 TourAPI live 응답과 카카오 지도 타일·핀 표시를 검증했다. 결과 JSON의 `apiRequests`는 브라우저에서 우리 서버로 보낸 경로별 요청 수다. 공공기관 upstream 호출 총수나 성공률로 해석하지 않는다. 원문 응답·키·전체 요청 URL·인증 헤더는 결과에 넣지 않는다. 지도 키는 허용 도메인으로 제한된 공개 JS 키이며 공공데이터 키는 서버에만 둔다.

공공 API 6종 표본 인증 결과는 [기존 API 검증](api_runtime_verification.json)을 따른다. 앱에서 사용하는 국문·무장애·기상청과 인증만 확인한 집중률·중심·연관 관광지를 구분한다. 공개 카페·현충시설 원천과 TourAPI 장애 대안은 같은 품질/운영 확인 수준으로 표현하지 않는다.

## 재현

```sh
cd web
npm ci
npm run dev
# 다른 터미널, Chrome과 Edge가 설치된 환경
npm run test:browser
# 키 없는 CI와 같은 실패 경로
npx playwright install chromium
QA_BROWSER_CHANNELS=chromium QA_CASES=small,desktop QA_LIVE=0 npm run test:browser
```

`QA_EDGE_EXECUTABLE`로 작업용 Edge 경로, `QA_OUT_DIR`로 결과 폴더, `QA_BASE_URL`로 검토 사이트를 지정할 수 있다. 비공개 배포 검사는 임시 `QA_AUTH_TOKEN`을 환경으로 전달하고 **해당 사이트 origin에만** 인증 헤더를 붙인다. 토큰을 명령 예시·파일·Git에 기록하지 않는다. 이 스크립트는 QA 전용 새 컨텍스트에서 임시 기록을 만든다.

## 남은 범위

실제 Android Chrome·iPhone Safari, 설치형 PWA, 200% 브라우저 확대, 화면 읽기 도구, 부모·장병 참여 사용성, 현장 운영 검증은 수행하지 않았다. 가족 초대는 같은 브라우저 시연이며 별도 기기 동기화가 아니다. 전체 lint의 기존 규칙 오류도 이 작업에서 해결·통과했다고 주장하지 않는다. 대표 여행안 2개와 5군 기본 점검, 심사 접근 설정, 지정 제출물 순으로 이어간다.
