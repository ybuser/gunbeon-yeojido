# 한 수 보태기 · 여행 기록 수정

2026-09-09 · ① 웹·앱 개발 부문 · Sites v13 공개 배포·운영 검증 완료

## 제품 결정

댓글창 대신 여행자가 질문 하나를 고르고, 방문자가 **대신 이곳 / 한 곳 보태기 / 조금 여유 있게** 중 한 가지로 공개 관광지에 제안한다. 실제 일정에 쓰이는 경험과 ‘이 공개안으로 내 여행 만들기’를 참여 동기로 삼는다. 바이럴 효과는 아직 검증되지 않은 가설이다. 벤치마크 공식 링크와 참고 범위는 `reports/advice_benchmark.md`를 본다.

첫 범위에는 공개 피드, 팔로우, 순위, 자동 SNS 게시, 검증되지 않은 방문·군인 인증을 넣지 않았다. 자유 댓글 대신 구체적인 장소와 이유 선택으로 제안을 짧고 이해하기 쉽게 만든다. TourAPI 관광지·음식점 검색은 정상 제공한다. 장소 검색·상세의 정상 범위를 용량 문제 때문에 축소하지 않았다.

## 사용자 흐름

1. 내 여행의 준비 중인 계획에서 **한 수 부탁하기**. 질문과 공개할 관광지를 확인하고 링크 발행.
2. 방문자는 `/p/{id}`로 비밀번호·가입 없이 열람한다. 기존 개인/그룹 화면과 일반 API의 1234 입구는 유지한다.
3. 특정 관광지를 대체·추가·덜어내는 제안 1개와 이유를 보낸다. 같은 브라우저에서 기존 제안을 삭제하고 새로 낼 수 있다.
4. 작성자는 **받은 한 수 보기 → 내 계획에서 검토**. 기존 개인 날짜·만남·복귀 기준을 보존한 편집기에서 결과를 검토한다. 취소하면 원본 유지. 저장 성공 뒤에만 공개 ‘반영됨’ 표시.
5. 저장과 서버 표시 사이 연결 실패는 `adviceReceipt`로 복구한다. 받은 한 수에서 다시 표시를 마무리한다. 이 버튼은 저장된 개인 계획을 재검사하며 장소를 중복 추가하지 않는다.
6. 참여자는 공개 관광지 순서로 새 여행을 시작한다. 테스트 입장 후 가져오기 미리보기→새 개인 편집기를 거친다. 원본 날짜·출타·그룹 권한·스탬프는 복사하지 않는다.

공개 여행안은 발행 당시의 스냅샷이다. 이후 개인 편집은 자동 공개되지 않는다. 제안 카드에는 개인 계획에 반영했음을 표시하고, ‘반영 표시 취소’는 공개 표시만 바꾼다. 완료한 기록과 진행 중 출타는 제안으로 수정하지 않는다.

## 여행 기록

- **기록 수정:** 여행 이름, 실제 다녀온 장소, 방문 스탬프를 수정. 기존 완료 날짜와 계획 장소·시간 보존. 조회 대기인 기존 방문 ID를 조용히 삭제하지 않는다.
- **계획으로 되돌리기:** 확인 후 같은 여행 ID·장소·시간을 유지하고 완료 정보/방문 스탬프만 제거. 휴가 씨앗 준비 기록 보존. 현재 출타를 자동 시작하지 않는다.
- **새 여행으로 가져오기:** 원래 기록은 유지하고 새 ID/빈 스탬프의 계획으로 복사.
- 이전 스탬프 기반 기록에서 모든 방문 스탬프를 해제해도 `recordStatus`로 기록 분류를 유지한다. 실제 방문 날짜를 새로 지어내지 않는다.
- 개인 자유 제목은 기존 공유 카드 원칙대로 공개하지 않는다. 이름 수정은 내 여행 이름에 적용되며 이미 내보낸 이미지가 바뀌지는 않는다.

## 공개 범위와 운영

- D1에는 사용자가 발행한 공개 장소 ID·순서·권역·질문, 선택형 제안과 반영 상태만 저장. TourAPI 원문·사진 응답은 저장하지 않는다.
- 공개 요청 입력의 `source`나 숫자 ID를 신뢰하지 않는다. 서버의 통일부/보훈부 카탈로그 또는 실제 TourAPI 상세로 강원 관광지임을 확인한다.
- 개인 자유 제목, 날짜/정확 시각, 만남·복귀 장소, 수동 장소, 좌표, 주소, 그룹/실명/부대 정보는 공개 DTO에서 제외한다.
- 관리·참여용 브라우저 권한은 서명된 HttpOnly/SameSite 쿠키이며 URL에 넣지 않는다. DB에는 해시만 저장한다. 정식 계정 복구/기기 간 권한 동기화는 아직 없다. 쿠키를 지우면 그 브라우저의 관리/수정 권한을 잃는다.
- 공개 링크 30일 만료. 마감은 읽기는 유지하고 새 제안을 막는다. 삭제는 D1 공유/제안/신고를 제거한다. 만료된 공유도 작성자는 개인 화면에서 삭제할 수 있고 방문자는 종료 화면의 ‘내가 남긴 제안 삭제’로 본인 제안만 삭제할 수 있다. 외부에 이미 내려받은 이미지를 원격 삭제하지 않는다.
- CSRF·JSON 크기 8 KiB·서버 검증·제안 고유 ID/방문자별 유일 인덱스·조건부 INSERT/UPDATE를 적용한다. 신고는 작성자에게 표시하며 숨기기는 작성자만 한다.
- 자동 남용 억제만 추가: 서명된 브라우저 세션을 기준으로 제한하고, 새 세션에는 20배 넓은 edge 진입 제한을 적용한다. 같은 통신사·공유망 사용자를 한 사람처럼 묶지 않는다. 원 IP는 저장하지 않는다. 브라우저별 공개 읽기 60회/분, 검색 45회/분, 제안 20회/10분, 발행 12회/10분. 계정의 TourAPI 승인량과 별개의 익명 공개 기능 보호다.
- 한 페이지에 제안 12개씩 조회하고 더 보기로 이어진다. 여행당 최대 60개, 작성자당 활성 공유 30개. 내용 규모를 화면/운영에서 감당하기 위한 테스트 단계 범위다.
- 인스타: 사진 저작권/CORS에 의존하지 않는 자체 타이포그래피 PNG + ‘다음: 링크 복사’ + 사용자가 링크 스티커로 게시. X는 공식 Web Intent 작성창만 연다. 게시 완료로 집계하거나 자동 게시하지 않는다.

## 검증 기록

실행 결과와 실제 화면은 `reports/qa/advice/`에 최종 반영한다. 코드 리뷰에서 발견한 호출 증폭, 신고 전달, 삭제/재제안 경쟁, 12곳 추가 제한, 만료 후 삭제 문제는 수정하고 회귀 검사한다. 사전 리뷰 문서는 당시 초안의 발견 사항이며 최종 미해결 목록이 아니다.


### 실행 결과

- TypeScript와 85개 단위 검사 통과.
- D1 실제 API 10시나리오: 비밀번호 입구, 공개 whitelist, metadata, CSRF/IDOR, 중복 제출, 신고, 삭제 후 재제안 경쟁, 채택/숨김, 마감/삭제 검사 통과.
- Chrome153 / Edge152에서 360×740, 430×932, 1440×900, 1920×1080 각 화면으로 발행→제안→취소→검토·저장→기록 수정/복원→공개안 가져오기 통과. 실제 휴대폰 검사가 아니라 데스크톱 브라우저 viewport/touch 모의다.
- 최종 Chrome360/1440·Edge360에서 만료 화면을 410 응답으로 재현하고, 실제 D1의 본인 제안 삭제까지 추가 통과. 공유 전체를 30일 기다린 실험이 아니다.
- 실제 서버 TourAPI: 고성 ‘카페’ 검색3개, 선택한 TourAPI 장소 상세 검증201, 공개 재조회 결측0. 원문 응답·키를 증빙에 저장하지 않았다.
- 가이드 19개 실제 캡처 로드와 360/1440 반응형·반복 사진 메모리 재사용 통과. UI 런타임 예외·가로 넘침 없음.
- 사용성/실제 SNS 검증 후속은 [#20](https://github.com/MySonIsSoldier/gunbeon-yeojido/issues/20). 실제 인스타/X 게시, 실제 스마트폰 Safari, 정식 관리권 복구는 아직 미검증·미구현 범위를 구분한다.
