# API 한도 대응 실행안

2026-09-08 · 군번여지도 강원 · **① 웹·앱 개발 부문** · 조사/준비 완료, 아래 코드 변경과 계정 신청은 예정

**권고: TourAPI는 운영계정 증설과 요청 구조 개선을 함께 진행한다. Kakao는 현재 앱의 무료 쿼터 적용을 확인하고 지도 재생성을 먼저 줄인다. 관광 데이터 DB는 별도 저장 절차의 답변에 맞춰 적용한다.** 키를 더 만들거나 매 요청마다 다른 공급자로 바꾸는 방식은 선택하지 않는다.

## 1. 확인된 문제와 아직 모르는 것

| 항목 | 확인된 사실 | 추가 확인 |
|---|---|---|
| TourAPI | 9/8 실제 `KorService2/areaBasedList2`가 HTTP 429 / 제공자 코드 22(일일 한도)를 반환. 같은 점검의 법정동 코드 조회는 성공 | 현재 승인 트래픽, 서비스/오퍼레이션별 집계, 남은 양, 초기화 시각 |
| Kakao | 마지막 공개 지도 시나리오는 실제 SDK로 성공. 과거 `disabled OPEN_MAP_AND_LOCAL service`는 사용 설정 오류였음 | 실제 쿼터 초과 발생 여부, 무료 배지, 오늘 지도 사용량·이번 달 전체 사용량 |
| 관광 응답 DB | 현재 서버에 적재하지 않음. 오류 차단 메타데이터만 D1에 저장 | 공식 저장 신청서와 허용 범위, 페이지 메모리 재사용 포함 |

현재 키를 다시 호출해 한도를 소모하지 않고 기존 [실측 및 정책 기록](tourapi_operations_policy.md), [공개 지도 검증](qa/discovery/public-flow.json)과 코드를 대조했다. 위 성공 기록은 현재 잔여 쿼터를 보장하지 않는다. 인증키는 수집할 필요가 없다.

## 2. TourAPI: 가장 먼저 운영계정 증설 준비

국문 서비스는 무료이며 공식 카탈로그에 개발 트래픽 1,000, 운영은 활용사례 등록 후 증가 신청·심의승인으로 안내된다. 현재 우리 승인값을 1,000으로 단정하지 않는다. [공공데이터포털 국문 서비스](https://www.data.go.kr/data/15101578/openapi.do)

한국관광콘텐츠랩 FAQ는 운영계정 검토에 개발 호출 이력·서비스 식별·실제/출시 예정 서비스 URL과 설명을 요구하며 통상 약 1주를 안내한다. 이는 확정 처리 기한이 아니다. 현재 코드의 식별값은 `MobileApp=GunbeonGangwon`이다. FAQ의 AppName 표현을 보고 API에 미지원 `AppName` 파라미터를 추가하지 않는다. [공식 FAQ](https://api.visitkorea.or.kr/)

1. 공공데이터포털의 국문·무장애 활용 신청 화면에서 승인 트래픽과 오퍼레이션 사용량을 기록한다. 같은 일반키를 써도 서비스 승인/한도를 하나로 합쳐 해석하지 않는다.
2. [신청 문안](api_capacity_requests.md)에 서비스 URL·활용사례·화면 가이드·산출표를 붙인다. 국문부터 우선 제출하고 실제 사용하는 무장애도 필요량에 맞춘다.
3. 증설은 운영계정 신청/변경 창구에서 진행하고, DB는 TourAPI 담당 부서의 별도 절차로 문의한다. 최신 공모전 안내에서 운영계정은 선택 신청이지만 **현재 발생한 한도 문제 때문에 운영상 필요**하다.
4. 승인된 값과 적용 시점을 기록한 뒤 제한된 목록 조회 한 번으로 확인한다. 전체 재수집으로 복구를 시험하지 않는다.

### 호출량은 ‘앱 접속 수’가 아닌 외부 요청으로 계산

`web/lib/tour-api.ts`, `web/app/api/place-detail/route.ts`, `web/app/api/places/{search,resolve}/route.ts`, `web/components/passport-app.tsx` 정적 확인 기준. 성공 경로이며 페이지 메모리 재사용으로 생략된 요청은 제외한다.

| 사용자 동작 | 현재 공급자 요청 |
|---|---:|
| 새로운 권역 목록 | 국문 코드 2 + 관광/문화/행사/숙박/음식점 목록 5 = 7 |
| 페이지 메모리에 없는 TourAPI 장소 상세 | 국문 공통/소개 2 + 무장애 상세 1; DMZ/직접 입력 장소 제외 |
| 검색 한 페이지 | 국문 코드 2 + 키워드 1 = 3 |
| 저장된 TourAPI 참조 복원 | 미해결 고유 장소당 국문 상세 1 |
| 권역 무장애 후보 | 무장애 코드 2 + 목록 1 + 후보 상세 최대 4 = 최대 7 |

첫 권역 요청은 홈에 들어와도 실행되는 구조다. **일정/그룹만 확인하는 사용자의 목록 조회를 없애는 것**이 첫 개선이다. 현재 유형별 첫 100개를 가져오므로 ‘강원 전체 데이터 수집’으로 표현하지 않는다.

다음 산출은 이용 예측이 아닌 신청량 검토용 가정이다. 하루 500세션, 세션당 권역 2회·미캐시 TourAPI 상세 3회·검색 페이지 2회·저장 참조 4개·무장애 후보 0.5회로 두면:

| 국문 요청 구조 | 예시 요청/일 | 전제 |
|---|---:|---|
| 현재 구조 | 15,000 | 권역별 5유형 선조회 |
| 1차 개선 | 11,000 | 권역 조회마다 실제 필요한 유형 1개만 열기; 코드 조회 유지 |
| 2차 검토 | 7,000 | 위 조건 + 확인된 참조 코드 사용 방식이 허용되고 매핑 검증 완료 |

이 예시의 무장애는 최대 3,250회/일이다. 다른 유형을 더 열거나 페이징하면 그만큼 늘어난다. 재시도·QA·보조 API·향후 동기화량은 별도이며 1.5배 여유 계수는 임시 운영 가정이다. **최적화 후에도 개발 한도만으로 충분하다고 가정하지 않는다.**

재현: `node scripts/estimate_api_capacity.mjs 500`. [예시 입력·오퍼레이션별 신청량 JSON](api_capacity_model.json). 실제 수치를 받으면 입력과 계수를 고쳐 신청량을 확정한다. 10만 회 승인을 당연한 권리나 보장값처럼 요청서에 쓰지 않는다.

## 3. 추가 결제 없이 우선 줄일 요청

아래는 구현할 작업이지 현재 완료된 기능이 아니다.

- **화면 의도에 따른 조회:** 홈/그룹의 권역 목록 조회 0건을 목표로 한다. 저장한 TourAPI 참조 복원은 별도 요청이다. 목록은 검색·장소 추가 등 필요한 시점, 상세·무장애는 해당 장소를 펼칠 때 요청한다. 당일 여행에서 숙박·행사 5유형을 일괄 조회하지 않는다.
- **동일 동작 재실행 억제:** 빠른 중복 클릭은 진행 중 요청을 공유하고, 제목·시간·도보 변경은 표시 중인 장소로 재계산한다. 완료 응답의 지속 재사용은 기존 브라우저 메모리 정책 문의에 포함한다.
- **반복 코드 조회 정리:** 강원 및 7시군 코드를 검증 가능한 참조 설정으로 관리하는 방안의 허용 범위와 갱신 방식을 확인한다. 코드명·값을 임의 추정하거나 관광 콘텐츠 전체 캐시의 예외로 확대하지 않는다.
- **실패 종류를 분리:** 22는 일일 차단, 23은 초당 제한, 인증 오류는 설정 문제로 처리한다. 현재 모든 429에 적용한 10분 차단을 한도 복구 시점처럼 사용하지 않는다. 일일 한도는 운영자 확인/제공자 초기화 안내 후 단일 시험 요청으로 복구하고 동시 요청의 연쇄 재시도를 막는다.
- **전체 호출 계측:** 서비스/오퍼레이션/날짜/성공·오류/지연만 합계로 기록하고 공급자 콘솔과 대조한다. 원문 키·개인 만남 좌표·일정·사용자 식별값을 통계에 저장하지 않는다.
- **심사와 운영 분리:** 회귀 테스트는 기록된 합성 응답을 기본으로, 실제 인증 점검은 제한된 별도 검사로 수행한다. 실제 TourAPI 활용 이력과 공개 기능 성공을 함께 남긴다. 가짜 성공 표시를 만들지 않는다.

서버 구현은 원자적 호출 예산 예약과 복구 시험 1건 잠금을 사용해 여러 Worker에서 동시에 재시도하지 않도록 한다. 잠금 만료는 프로세스 실패 회복을 위한 것이며 제공자 쿼터 초기화와 무관하다. 승인 한도 미입력 상태에서 무제한으로 가정하지 않는다.

## 4. DB는 허용 범위를 확인한 뒤 적용

일반 데이터 이용허락만 보면 저장 가능해 보이지만 한국관광콘텐츠랩은 콘텐츠의 로컬서버 캐싱을 금지하고, 개발 부문 FAQ는 부득이한 저장에 별도 신청을 안내한다. 신청만으로 가능한지 사전 회신이 필요한지는 명시되지 않았다. [공식 정책](https://api.visitkorea.or.kr/#/useServiceGuide/2), [공모전 저장 FAQ](https://lowly-polyanthus-1fb.notion.site/2026-36b5dce406e380e0a3d1f80525667a11#3715dce406e380cebabbe62a3ce7b9e8)

준비한 요청 범위는 **강원 접경 5군 + 춘천·속초의 필요한 장소 필드만**이다. 이미지 파일 복제는 별도로 묻고, 식별자/사진 URL/사용자 일정에 남는 일부 필드/페이지 메모리도 각각 확인한다. 상세 정책과 문의 문안은 [저장 검토 보고서](tourapi_operations_policy.md#7-저장-방식-신청-문의-이메일-초안--미발송)에 있다.

허용 시 설계: 정규화 장소와 원천 ID·수정시각·확인시각·이용조건 저장 → 변경 확인 작업 → 새 버전을 임시 영역에서 검증 → 성공분 반영 → 삭제/이용조건 변경 반영. 운영·예약처럼 중요한 내용은 열람 시 확인 상태와 원문 링크를 제공한다. 승인된 갱신 주기를 따르며 증분 API의 지원 범위도 실제 매뉴얼/응답으로 확인한다. 실패한 수집을 빈 목록으로 덮어쓰지 않는다. 허용 전 이 파이프라인과 스케줄은 실행하지 않는다.

저장이 허용되지 않아도 위 2–3장의 증설·선택 조회·오류 억제로 운영한다. 별도 이용조건의 DMZ/현충시설 기본 데이터는 출처를 구분해 유지하고, 외부 실패 때 관광공사 최신 응답으로 가장하지 않는다.

## 5. Kakao: 무료 적용 확인 → 인스턴스 유지 → 사용량에 맞는 증설

일반 무료 기준은 전체 API 월 300만, Web 지도 일 30만이다. 2026-07-21 이후 활성화 앱은 개발자 계정의 첫 카카오맵 앱에만 무료 쿼터가 적용되므로 **현재 군번여지도 앱의 무료 배지 확인이 먼저**다. 기존 활성 앱 유지 조건과 추가 쿼터의 월간 합산 제외 조건까지 함께 본다. [공식 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota), [무료 적용 정책](https://developers.kakao.com/docs/ko/kakaomap/common)

- 일정 제목/출발 시각을 수정하면 `mission` 객체가 바뀌고 지도 효과가 `new Map`을 다시 실행한다. 지도 인스턴스는 유지하고 **장소·좌표·순서가 바뀔 때만 핀과 화면 범위를 갱신**한다. 제목 수정 때 줌도 유지한다.
- 두 지도 컴포넌트의 SDK 로딩을 한 개의 공유 Promise로 정리한다. 목록/홈에서는 지도를 만들지 않는다. 장소 선택의 지도 기능은 유지하고, 편집 화면 보조 지도는 명시적으로 열 때 생성한다.
- SDK 요청과 지도 생성의 공식 집계 설명에 차이가 있어 앱 이벤트 두 종류를 각각 세고 콘솔과 대조한다. 객체 재사용으로 ‘요금 N% 감소’를 먼저 약속하지 않는다.
- 현재 앱의 길찾기는 공식 카카오맵 외부 링크다. 신규 경로/로컬 검색 유료 API를 불필요하게 붙이지 않는다. 지도 한도 때는 장소 목록·일정 편집과 외부 지도 링크를 계속 제공한다. 지도 타일을 복제해 서비스하지 않는다.
- 무료 범위 안이면 유료 전환 없이 운영한다. 초과가 확인되면 BizWallet/유료 설정의 예상 비용을 검토한다. 지도 Web 추가 요금은 0.1원/건(부가세 별도)이며 무료 자격에 따라 계산이 달라진다. 월 1만원 경보를 제안할 수 있지만 **내부 경보이며 카카오맵 청구의 강제 상한이라고 보장하지 않는다.**

계정별 선택표·비용 예시·집계 확인 문의는 [카카오 상세 실행안](kakao_capacity_strategy.md)에 준비했다. 유료 활성화·결제카드 등록·문의 발송은 실행하지 않았다.

## 6. 실행 순서와 완료 조건

| 순서 | 작업 | 완료 판단 |
|---|---|---|
| 바로 준비 | 콘솔 수치 기록, 운영계정 신청 자료와 저장 문의 분리 | 신청자·실제 한도·요청량·URL·활용사례가 있는 제출본 |
| 개발 1–2일 예상 | 목록 지연 조회, 유형 분리, 지도 유지, 22/23 및 단일 복구 시험 | 홈의 권역 목록 조회 0건, 비지리 편집 지도 재생성 0회, 중복 동작 추가 요청 0건; 모의 응답 회귀 검사 |
| 다음 1일 예상 | 외부 요청 합계·예산/복구 상태, 축소 운영 UI | 키 없는 통계, 한도 상태별 정상 안내, 제한된 실연동 1회와 콘솔 대조 |
| 별도 회신 이후 | 승인 범위 DB/동기화 또는 실시간 운영 유지 | 저장 절차·범위 문서화, 삭제/갱신·출처·장애 복원 검증 |
| 병행 후속 | 하루 여권·여유 조정 | [제품 제안서](memorable_experience_proposal.md)의 출발 전 비교·적용·되돌리기 |

기간은 개발 작업량 추정이며 승인 대기·QA 결과에 따라 달라진다. 공모전 제출은 기존 확인 기록상 **9/21 16:00 KST**다. 기능심사 전 실제 TourAPI 성공 화면과 호출 이력을 확보하고, 요청량이 줄었다는 코드 증거와 승인 변경을 함께 보관한다. 영상/장식 때문에 이를 뒤로 미루지 않는다.

## 7. 이번 준비 작업의 검증·관리

- 호출량 모델의 오퍼레이션 합산·1세션 환산·증설 올림·JSON 일치와 잘못된 입력 거부를 Node에서 확인했다. 외부 API는 호출하지 않았다.
- 다른 검토자가 공식 조건과 코드 호출 산식을 교차 확인했다. 홈의 ‘목록 조회 제거’와 남는 저장 참조 복원을 구분해 문구를 수정했다.
- 제품 제안 시안은 [4개 환경 검사 기록](qa/planning-strategy/mockup.json)과 [디자인 제안서](memorable_experience_proposal.md)에 남겼다. 서비스의 신규 동작 검증이나 성과 측정은 아니다.
- 구현 후속: [API 한도 대응 #15](https://github.com/ybuser/gunbeon-yeojido/issues/15), [하루 여권 적용 #16](https://github.com/ybuser/gunbeon-yeojido/issues/16). 준비 문서가 머지되어도 구현 항목은 열린 상태로 유지한다.
- 이번 변경은 문서·산출 스크립트·시안 사진이다. 운영 코드·배포·결제·콘솔 설정·외부 문의 발송은 변경하지 않았다. 현재 계정 수치가 들어오면 신청량과 비용 판단을 갱신한다.
