# API 한도 대응 실행안

2026-09-09 · 군번여지도 강원 · **① 웹·앱 개발 부문** · 계정 신청·문의는 미제출·미발송

**TourAPI는 정상 기능에 필요한 충분한 트래픽을 정식으로 확보하는 것이 우선이다. 관광·문화·행사·숙박·음식점 5유형, 검색·상세·무장애 정보를 유지한다. Kakao는 무료 적용과 실제 사용량을 확인하고, 불필요한 지도 재생성만 없앤다.** 데이터 저장 절차는 증설과 별도로 진행한다.

| 항목 | 확인된 사실 | 남은 확인 |

## 2. TourAPI 정식 확대 경로

9/9 확인한 [한국관광콘텐츠랩 FAQ](https://api.visitkorea.or.kr/#/cmsFAQ)는 운영계정 신청 기본 트래픽을 **일 100,000건**, 기존 운영계정의 추가 증설을 **운영팀 사유 검토**로 안내한다. 일일 사용량은 매일 00시에 초기화된다는 안내다. 이는 **우리 계정에 현재 10만 건이 승인됐다는 뜻이 아니다.** 서비스/오퍼레이션별 적용 단위와 실제 반영은 확인해야 한다.

[국문 서비스 카탈로그](https://www.data.go.kr/data/15101578/openapi.do)는 무료·개발 트래픽 1,000·운영 심의승인을 안내한다. FAQ상 운영 검토는 개발 호출 이력, 서비스 식별·URL·내용을 확인하며 약 1주가 걸릴 수 있다. 확정 처리 기한은 아니다. 호출 식별값은 공식 요청 규격에 맞는 `MobileApp=GunbeonGangwon`을 유지한다. [호출 안내](https://api.visitkorea.or.kr/#/useOpenapiManual)

1. **포털 운영계정 전환/변경 준비:** 현재 국문·무장애 승인 상태와 사용량을 기록하고, 서비스·실제 API 활용 화면·정상 수요 산출표를 준비한다.
2. **TourAPI 운영팀에 전체 수요 문의:** 국문과 무장애 등 실제 쓰는 서비스의 트래픽 확대를 함께 요청한다. 이미 운영계정이라도 추가 증설 경로를 이용할 수 있다.
3. **공모전 지원 경로 병행:** 예선 통과, 9/21 16:00 KST 제출·기능심사 준비 상황을 전달해 신속 검토 또는 한시 증설 가능 여부를 문의한다. 자동 특례나 무제한 제공은 확인되지 않았다.
4. **승인·반영 확인:** 포털 신청번호와 운영팀 회신을 연결해 승인량·단위·적용일을 기록하고 정상 추천·검색·상세·무장애 흐름을 실제 화면에서 검증한다.

공모전 [공식 인증키·운영계정 가이드](https://drive.google.com/file/d/1iAy4zLbWT4gWbc7PkW2mujdQBFD-2-BC/view)는 **실제 활용 API 중 대표 1개, 팀별 1회 신청**을 안내한다. 따라서 국문을 대표로 준비하고, 무장애를 포함한 다른 서비스 확대의 적용 범위·별도 절차는 운영팀에 함께 확인한다. 임의로 여러 공모전 신청을 만들지 않는다. 전환은 공모전상 선택이며 승인/반려 자체는 심사와 별개지만, 실제 서비스 한도 해결은 필요하다.

## 3. 정상 기능을 기준으로 요청량 계산

앱 API 1회와 공급자 요청 1회는 다르다. 다음은 현 코드의 성공 경로이며 페이지 메모리에서 재사용된 요청은 제외한다.

| 사용자 동작 | 공급자 요청 |
|---|---:|
| 새 권역 목록 | 국문 코드 2 + 5유형 목록 5 = 7 |
| 미재사용 TourAPI 장소 상세 | 국문 공통/소개 2 + 무장애 상세 1 |
| 검색 한 페이지 | 국문 코드 2 + 키워드 1 = 3 |
| 저장한 TourAPI 참조 복원 | 미해결 고유 장소당 국문 공통 상세 1 |
| 권역 무장애 후보 | 무장애 코드 2 + 목록 1 + 후보 상세 최대 4 |

**하루 500세션이라는 가정**에 세션당 권역 2회·상세 3회·검색 페이지 2회·미해결 참조 4개·무장애 후보 조회 0.5회를 적용하면 국문 **15,000회/일**, 무장애 **최대 3,250회/일**, 합계 **최대 18,250회/일**이다. 실측 사용자 수나 확정 신청량이 아니다. 유형별 첫 100건 조회 구조이며 전체 관광지 풀을 수집한 수치도 아니다.

산출: `node scripts/estimate_api_capacity.mjs 500`. [입력·계산 결과](api_capacity_model.json), [오퍼레이션별 표](api_capacity_requests.md). 추가 페이지·이미지 API·향후 연동·QA·피크 수요를 더하고 실제 승인 단위에 맞춰 요청량을 확정한다. 유형을 줄여 호출량을 낮추는 과거 비교값은 운영 목표로 쓰지 않는다. 공식 기본 10만 전환을 출발점으로 검토하고, 정상 수요가 적용 한도를 넘으면 추가량을 요청한다.

## 4. 기능을 유지하는 안정성 개선

- **가치 없는 중복만 제거:** 같은 동작의 중복 클릭·진행 중 동일 요청을 합친다. 제목·시간 편집은 이미 표시한 장소로 다시 계산한다. 추천 범위·검색 깊이·사진·상세·무장애를 한도 목표 때문에 줄이지 않는다.
- **제공자 제한을 정확하게 구분:** 공식 오류 표에서 22는 일일 한도, 23은 초당 한도다. JSON/XML 응답 모두 분류하고, 23에는 짧은 대기 후 사용자가 다시 조회할 수 있게 한다. HTTP 429만으로 일일 한도를 단정하지 않는다. [공식 오류 코드](https://www.data.go.kr/tcs/dss/selectErrCodePopupView.do)
- **관측을 증설 판단에 사용:** 서비스·오퍼레이션별 호출 수, 성공률, 22/23, 지연을 기록해 공급자 콘솔과 대조한다. 승인값 미확인을 임의의 낮은 자체 한도로 바꿔 정상 기능을 차단하지 않는다. 키·개인 일정·만남 좌표는 통계에 넣지 않는다.
- **정상 이용과 QA를 구분:** 자동 회귀 검사는 합성 응답으로 하고 실제 API 기능 성공은 별도로 확인한다. 불필요한 반복 검증을 피하되, 심사에 필요한 실제 호출 이력과 성공 화면을 확보한다.

22/23 JSON/XML 분류·Retry-After 우선·초당 제한 기본 30초 대기를 구현하고 단위 검증했다. 자동 재시도 루프는 없다. 일일 한도는 기본 10분 후 사용자의 새 요청으로 다시 확인할 수 있다. 기존 10분 오류 차단은 제공자 초기화 시각이 아니며, 완료 여부는 코드·테스트 기록으로 확인한다.

## 5. 저장 방식은 별도 신청

한국관광콘텐츠랩은 로컬서버 콘텐츠 캐싱 제한과 서버 구축 방식 신청을 안내한다. 공식 FAQ에 따라 신청자명·API 서비스명·인증키를 지정 비공개 경로로 전달해 양식을 받는 절차를 확인한다. 검토는 최소 3–5일 이상 안내이며, 신청만으로 저장을 시작할 수 있는지는 답변받아야 한다. [공식 정책](https://api.visitkorea.or.kr/#/useServiceGuide/2), [공식 FAQ](https://api.visitkorea.or.kr/#/cmsFAQ)

요청 범위는 강원 접경 5군·춘천·속초의 필요한 장소 필드다. 사진 URL/파일, 사용자 일정의 장소 참조, 브라우저 페이지 메모리, 동기화·삭제 주기를 각각 묻는다. 허용 범위가 정해지면 정규화 → 변경 확인 → 검증 후 반영 → 삭제/이용조건 변경 반영을 구현한다. 실패 응답으로 기존 데이터를 지우지 않는다. **저장 회신을 기다리는 동안에도 증설과 정상 실시간 기능은 진행한다.** 자세한 판단은 [저장 운영 정책](tourapi_operations_policy.md)에 있다.

## 6. Kakao 운영 판단

일반 무료 기준인 전체 API **월 300만**과 Web 지도 **일 30만**을 함께 본다. 2026-07-21 이후 활성화 조건과 기존 무료 앱 유지 규칙 때문에 현재 앱의 무료 배지를 먼저 확인해야 한다. 추가 쿼터가 적용된 유료 API의 월간 합산 제외 조건도 별도다. [공식 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota), [앱별 무료 적용](https://developers.kakao.com/docs/ko/kakaomap/common)

- 같은 지도 화면에서 제목·시간 편집 시 객체 유지와 좌표 변경 시 핀 갱신을 구현했다. 다른 화면으로 이동했다 돌아오는 정상 지도 생성까지 금지하지 않는다.
- SDK 요청/지도 생성 집계에 관한 공식 답변에 차이가 있어 두 이벤트와 콘솔을 대조한다. 재사용에 따른 비용 절감률을 미리 확정하지 않는다.
- 실제 무료 적용·사용량을 확인한 후 부족하면 정식 추가 쿼터/유료 설정을 검토한다. Web 지도 추가 요금은 건당 0.1원, 부가세 별도다. 결제·설정 변경은 하지 않았다. [유료 설정 안내](https://developers.kakao.com/docs/ko/app-setting/paid-api)
- 외부 카카오맵 길찾기 링크는 유지한다. 지도 장애 시 일정 편집·장소 목록을 이용할 수 있게 하되, 정상 지도 기능을 비용 목표 때문에 숨기지 않는다. 내부 비용 경보는 카카오의 강제 청구 상한이 아니다.

정책·비용 예시·계정 질문은 [Kakao 상세 자료](kakao_capacity_strategy.md)를 참고한다. 이 문서의 지도 구현 상태가 이전 조사 시점의 코드 설명보다 최신이다.

## 7. 다음 완료 조건

1. 계정 승인량·사용량과 신청 주체를 채워 포털 대표 신청, 운영팀 증설 문의, 사무국 지원 문의를 제출 가능한 상태로 완성한다.
2. 5유형 추천·검색·상세·무장애가 유지되는 회귀 검사, 22/23·인증 오류·일반 429 검사, 지도 편집 검사를 남긴다.
3. 실제 증설이 반영되면 승인 범위와 정상 API 화면을 확인하고 심사 자료에 반영한다. 신청·승인·구현·배포는 각각 구분해 기록한다.
4. 저장 절차 답변 후 해당 범위만 구현한다. [API 대응 이슈 #15](https://github.com/MySonIsSoldier/gunbeon-yeojido/issues/15)에 근거와 검증 결과를 연결한다.

**이 문서는 신청 준비와 개발 방향이다. 트래픽 증설, 데이터 저장 허용, 유료 결제 또는 외부 문의가 완료됐다는 뜻이 아니다.**
